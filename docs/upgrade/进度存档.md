## 三、已经定死、不要再改的口径

改动这些等于推翻前两天或 Day 4 的评审结论，要改必须先说明理由。

- 任务状态 9 个、终态 4 个，转换表 T01–T19、非法转换 I01–I11，见 [job-state-machine.md](contracts/job-state-machine.md)。
- 创建任务的判定顺序固定：同 key 同 body 返回原任务；同 key 不同 body 返回 409 `idempotency_mismatch`；同活动指纹返回 200 并带 `X-Existing-Job`；同股票同日期不同配置且活动返回 409 `active_conflict`；否则 201。见 [idempotency-conflicts.md](contracts/idempotency-conflicts.md)。
- 崩溃边界 B1–B6 里只有 B1 和 B5 可以无人工介入自动恢复。B4 明确**不**自动判成功。见 [crash-boundaries.md](contracts/crash-boundaries.md)。
- 报告 = meta + 13 个固定 section id。`rating` 只按 `**Rating**:` 精确解析，解析失败写 `unknown`，绝不用关键词猜。`signal` 由 `rating` 固定映射派生。旧版关键词扫描结果只作 `signal_legacy` 存档。见 [report-schema-v1.md](contracts/report-schema-v1.md)。
- 历史导入报告强制 `generated_at` 为空、`generated_at_source=unknown`、`data_quality_status=absent`、`chart_snapshot_status=none`。
- 前端禁用词：停止、重跑、任务不存在。用户可见文案对照表见 [semantic-dictionary.md](contracts/semantic-dictionary.md)。
- 性能测量口径：DOM 签名静默期 + 400ms rerun 缓冲，首屏数字里含约 1.9 秒固定开销，新旧对比必须用同一口径和同一个脚本。

Day 4 新增、同样不许回改：

- 数据信封只有四态 `ok / empty / error / stale`，部分成功用 `partial` 布尔加 `failed_blocks` 表达，不加第五个状态。
- `is_stale` 恒等于 `status == "stale"`；`empty` 与 `error` 时 `data` 与 `as_of` 必须为 null。
- 数据源失败用 HTTP 200 + 信封；请求不合法、对象不存在、状态冲突用 4xx/5xx。两者不互相顶替。
- 数据源错误码只有四个：`upstream_timeout`、`upstream_error`、`upstream_rate_limited`、`data_parse_error`。
- P0 未实现的市场接口返回 501 `not_implemented`，不用 404 冒充，也不返回假数据。
- 任务按钮只按 `allowed_actions` 渲染；`stages` 固定 12 个阶段，id 与顺序不许改。
- 暂停后的「继续」走同任务动作；中断后的「从检查点继续」才创建新任务。两者文案不得混用。
- 多区块接口的顶层 `as_of` 取主区块（快照 `quote`、概览 `indices`）。
- SSE 序号在同一任务内连续；对账补发的事件分配新序号追加在尾部；重连只读，410 后只允许读任务详情。
