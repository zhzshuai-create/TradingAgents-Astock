## 四、P3 范围与出口判据

依据：`docs/AStock_Pro_专业投研工作台全面升级计划_2026-10-28.md` 第 4.6 至 4.8 节与第九节 P3 行；`docs/upgrade/contracts/api-v1.md` 第 2 节；`docs/upgrade/contracts/core-wireframes.md` 第 5、6 节；`docs/upgrade/contracts/report-consistency-tests.md`。

P3 要交付六组能力：

- 报告库：游标分页、股票/分析日期/评级筛选、同股票同日期多版本、来源角标、返回恢复筛选与滚动位置。
- 报告阅读器：桌面粘性目录与当前章节高亮、移动目录抽屉、章节深链 `#sec-xxx`、决策卡、元信息、缺失字段显示「—」。
- 统一报告结构：网页、Markdown、PDF 都从同一份 ReportDTO 生成，章节集合与顺序一致。
- 旧报告导入：扫描旧 `full_states_log_*.json`，按路径加内容哈希幂等导入，不伪造任务与生成时间。
- 按需导出：Markdown 直接下载；PDF 只在用户点击后生成，缓存键固定，失败不影响正文。
- 兼容投影：把同股票同日期最新成功报告投影到旧版文件，旧版仍能打开；投影失败不影响新版成功状态。

P3 完成必须同时满足四条出口判据：

1. 同一份模拟报告，新旧版本的章节集合、顺序与正文一致；网页、Markdown、PDF 三端章节标题序列相同。
2. 打开报告零副作用：不生成 PDF、不请求外部行情、不写文件、不改报告行；GET 前后表行数、文件与网络计数不变。
3. 同股票同日期可以多版本并存：每次成功分析产生独立 `report_id`，重跑不覆盖旧报告，列表按 `generated_at` 倒序且 null 排最后。
4. 重复导出 PDF 命中缓存：同一 `report_id + content_hash + exporter_version` 第二次返回 200 与 `X-Export-Cached: 1`，不重新渲染。

性能按计划第 10.2 节验收：

- 报告元数据与正文 GET p95 不超过 500 ms，外部网络调用为 0。
- 1 万条报告元数据下，50 条分页加基础筛选 p95 不超过 500 ms。
- PDF 缓存命中下载准备不超过 500 ms；固定大报告首次 PDF 生成 p95 不超过 15 秒，失败时正文始终可读。

P3 完成后形成内部 MVP，但不切换默认入口。旧版仍是默认写入口，市场、日志、设置仍留给 P4/P5。

## 六、开工前必须先定的六个决定与三处契约缺口

以下六项决定与第七节的三处缺口都必须在 `p3-backlog.md` 里定稿；本票可以给建议，但不能让后续票边写边改。

### 1. O2：契约文件字节固定

- 问题：CT-08 按原始字节算哈希，冻结值按 LF 计算；仓库没有 `.gitattributes`，`core.autocrlf=true` 的全新检出会变成 CRLF，预检误报。
- 建议：在 `.gitattributes` 写 `docs/upgrade/contracts/** -text`，关掉该目录的行尾转换；用 `git worktree add --detach` 做一次全新检出并复跑 CT-08 证明。
- 不建议改 CT-08 的哈希口径；那会动冻结清单，属于解冻范围。
- 票位：可以放在 P3-00 的同一提交，也可以单开一张极小的 P3-00a；不能拖到 P3 出口前。

### 2. 导出记录与缓存持久化

- 问题：契约要求 `GET /exports/{id}` 在进程重启后仍能回答状态；当前没有导出表，`reports` 表也不该承担临时渲染状态。
- 建议：新增 `0007_report_exports` 表，字段至少 `export_id`、`report_id`、`content_hash`、`exporter_version`、`template`、`status`、`file_path`、`error_code`、`created_at`、`ready_at`；PDF 文件放 `TA_EXPORTS_DIR`，库里只存相对路径；缓存唯一键为 `report_id + content_hash + exporter_version + template`。
- 理由：内存字典不能跨重启；纯文件台账难做并发与状态查询；表加文件与现有 `reports` 表加报告文件的模式一致。
- 票位：P3-03 独占 `0007` 与导出服务。

### 3. 旧报告导入幂等

- 问题：ReportDTO 是 `additionalProperties: false`，没有地方放旧文件路径；`reports` 表也没有来源路径列。计划要求「旧路径 + 内容哈希」保证重复导入幂等。
- 建议：新增 `0006_legacy_imports` 表，主键 `(source_path, content_hash)`，另存 `report_id` 与 `imported_at`；报告行保持 DTO 原样，不往 payload 塞额外字段。
- 理由：路径改内容会生成新记录，重复扫描同一文件不新增；不破坏 DTO 冻结；`uq_reports_job_id` 对多个 NULL 允许，旧报告可以多行并存。
- 票位：P3-02 独占 `0006` 与导入脚本。

### 4. PDF 渲染器

- 建议：新建 `backend/app/services/export_service.py` 与 `pdf_renderer.py`，用已安装的 `fpdf2 2.8.9` 从 ReportDTO 渲染；`exporter_version` 用模块常量；字体发现可参考旧版的 Windows `msyh.ttc` / `simhei.ttf` 行为，但**不要 import `web.pdf_export`**。
- 理由：GF-06 规定后端不依赖 `web`；旧渲染器绑定了 Streamlit 时代的文本工具；新渲染器才能保证网页、Markdown、PDF 同源。
- 风险：中文 TTC 字体在 fpdf2 下的嵌入要先用一份真实长报告冒烟；字体缺失时导出应失败并给安全错误，正文与 Markdown 不受影响。
- 票位：P3-03。

### 5. 阅读器正文来源

- 建议：网页阅读器直接渲染 DTO 的 `sections`；`GET /reports/{id}/markdown` 只用于下载与三端一致性对照；PDF 也从同一 DTO 生成。
- 理由：章节 id、顺序与深链都来自 DTO；若网页改渲染 Markdown，还要从标题反推 `sec-xxx`，会出现第二套解析器。
- 对照方式：T9 比较 DOM 标题序列、Markdown 标题序列、PDF 书签序列是否都等于 DTO 中「存在且非空」的章节顺序。
- 票位：P3-05。

### 6. 兼容投影的警告面

- 问题：计划要求投影失败「必须显示兼容警告」，但冻结的 API 没有这个字段；报告 DTO 也不能加字段。
- 建议：P3 只做「投影失败写服务端日志与验收记录」，不伪造 UI 警告；若必须 UI 显示，走 `FREEZE-v1.md` 的解冻流程加一个明确字段，或把 UI 警告留到 P6 双栈阶段。
- 理由：不能为了满足一句文案偷偷扩契约；也不能把「已显示」写进评审而没有证据。
- 票位：P3-08 定实现，P3-09 在评审里如实写「已实现/未实现 UI 警告」。

### 7. 已发现的三处契约口径冲突

这三处必须在 `p3-backlog.md` 里写清采用哪一口径，不能留给实现时临场决定。

1. 生成日期筛选：计划第 4.6 节写「分析日期和生成日期筛选」，冻结的 `GET /reports` 只有 `date_from` / `date_to`，并明确按 `analysis_date` 过滤。建议 P3 只做分析日期筛选，生成日期筛选留到 P4 或走解冻流程；backlog 写明这是计划与冻结接口的差异。
2. 信号筛选：计划第 4.6 节写「信号筛选」，冻结接口与 W05 线框实际是 `rating` 多选（五档加 unknown）。按 `rating` 执行，不新增 `signal` 参数，也不在前端另做三档筛选。
3. T17 与 schema 冲突：T17 要求 `legacy_import` 报告导出后 `chart_snapshot_status = refetch_needed`，但 `report-schema-v1` 强制 `legacy_import` 的 `chart_snapshot_status = none`。建议把「补数」限定为导出产物上的标注（含补数时间），报告行仍为 `none`；不要为了 T17 改冻结 schema。P3-00 在 backlog 里写清 T17 的解释，P3-09 按该解释验收，并在评审里单列。

## 九、必须守的约束

- 一票一对话、一票一本地提交、不推送；开工前与收工前预检都必须 10 项 PASS。

- 报告 GET 零副作用；PDF 只能由 `POST /reports/{id}/exports/pdf` 触发；任何报告页面不得请求行情。
- 迁移只做新增式：`0005` 之后按 `0006`、`0007` 顺序，每张迁移由一票独占；要回退先 `alembic downgrade` 再 revert 提交。

- Markdown 禁用原始 HTML；外链新窗口打开并加 `rel="noopener"`；文件名与路径只按 `report_id` / `export_id` 查询，不接受任意路径。
- 旧版投影必须备份后原子替换；投影失败只警告，不改新版报告状态。

## 十、容易踩的坑

1. `reports` 表已经有行，但没有报告路由；不要以为接口已存在，也不要让前端先按假设字段开发。
2. `uq_reports_job_id` 只保证一任务一报告，不是「一股票一日期一报告」；不要加 `unique(ticker, date)`，那会杀掉多版本。
3. 旧报告导入禁止用文件 mtime 冒充生成时间；四个强制值是 `generated_at = null`、`generated_at_source = unknown`、`data_quality_status = absent`、`chart_snapshot_status = none`。
4. DTO 是严格 schema，不能往 `meta` 或 `payload` 塞 `source_path`；导入幂等靠独立台账。
5. 导入键是「路径 + 内容哈希」；同一路径改内容应新增记录，同一内容重复扫描应零新增。
6. 兼容投影会覆盖旧文件；必须先备份再原子替换，失败不能把新版报告标成失败。
7. 旧版 ticker 取 `log_file.parent.parent.name`；投影目录少一层，旧版就看不到。
8. `content_hash` 只对 `sections` 规范序列化计算，不含 meta、生成时间或导出模板；不要为了 ETag 改哈希。
9. Markdown 必须与网页、PDF 用同一序列化顺序；不要为下载另写一套标题拼接。
10. PDF 缓存键是 `report_id + content_hash + exporter_version`，模板白名单另算；命中才写 `X-Export-Cached: 1`。
11. 打开报告时若前端预取 Markdown 或导出，R-05 会直接失败；阅读器首屏只调 `GET /reports/{id}`。
12. 移动目录是抽屉，不是桌面表格；页面级 `scrollWidth` 必须等于 `clientWidth`，只有正文表格允许容器内横向滚动。
13. `ReportsPage` 与 `ReportDetailPage` 占位文案写的是 P5，P3 实现时要替换，不要照抄阶段号。
14. E2E 启动旧版时必须把 HOME/USERPROFILE 指到临时目录；否则会读到真实 `~/.tradingagents`。
15. 1 万条分页性能测 p95，不测平均值；数据生成脚本与结果 JSON 一起留存，但不把万行数据提交入库。
16. 不要为了省事 import `web.pdf_export`；GF-06 边界会失败，而且旧渲染器带 Streamlit 依赖。
17. `unsafe_text_report` 必须在网页、Markdown、PDF 三端都验；只在网页转义不算通过。
18. 深链章节不存在时停在顶部，不报错、不 404；这是契约行为，不是缺陷。
