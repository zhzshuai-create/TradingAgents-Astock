## 二、一次对话的固定流程

1. 读本卡与 `docs/upgrade/reviews/2026-11-08_P6主用观察.md`。
2. 预检：`.venv/Scripts/python.exe scripts/p0_preflight.py --full --smoke`，必须 10/10 PASS、工作区干净、HEAD 与 `git log -1` 一致；不一致先报告不动手。
3. 审计：`.venv/Scripts/python.exe scripts/stack_audit.py --date all`，异常必须为 0；确认 8600 / 8610 无监听。
4. 确认本次预算（约 17–27 分钟、27–40 次调用、0.27–0.37M tokens），得到批准后再发起。
5. 跑 1 个任务：

```bash
cd C:\Users\zhzsh\TradingAgents-astock
.venv/Scripts/python.exe %TEMP%\p6_04b_batch.py --start <N> --count 1
```

   - `N` 是本次索引：2 → 第 4 次运行，3 → 第 5 次，4 → 第 6 次，5 → 第 7 次。
   - 脚本自己起停后端：创建任务用 `job_id` 字段；只在 `succeeded/failed/interrupted/cancelled` 之后发 `CTRL_BREAK_EVENT`；停机后确认 8600 释放；任务未到终态即中止，不启动后续。
   - 后台运行；进度文件 `%TEMP%\p6_04b_progress.jsonl`，每次阶段切换追加一行。
6. 审计：`.venv/Scripts/python.exe scripts/stack_audit.py --date 2026-11-08`，五类全 PASS、异常 0。
7. 出记录块：`PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe %TEMP%\p6_04b_record.py --date 2026-11-08 --index <N>`，把它追加到当日记录，并更新当日任务表与审计输出。
8. 代码与文档分别本地提交；提交后复跑预检。

## 五、已知坑

1. 停机信号发给子进程组，驱动自身也在同一控制台；脚本里不要重复发信号，也不要在创建失败时误停后端。
2. 收到信号后 API 先停、worker 继续跑图，主进程等 30 秒后退出。
3. 中断任务的 `job_stages` 可能仍显示 `active`；以 `jobs.status` 为准。
4. 成功任务事件是 41 行（created 的 seq 为空 + seq 1..40）。
5. 调用数浮动大（27 / 31 / 40），判断重复看事件流，不看总次数。
6. 并行阶段 `started_at == finished_at` 正常，看 `duration_ms`。
7. 轮询间隔不要与 uvicorn 5 秒 keep-alive 重合；这是 11-08 09:52 中断的根因。
8. 数据源告警照旧：股东研究 `'dict' object has no attribute 'strip'`、CLS 新闻失败/超时、mootdx 走 sina 回退；只进记录，不在本票修。
9. 审计只读；SQLite 读 WAL 库会刷新 `jobs.db-shm`，`jobs.db` 与 `-wal` 字节不变。
10. 临时脚本放 `%TEMP%` 且不提交。
11. 报告 `rating/signal` 可能落库为 `unknown`：Trader / PM 结构化输出失败会改自由文本重试，正文有结论但字段缺失；判断看正文，不只看字段，不属五类异常（见 11-08 第 6 次运行）。
