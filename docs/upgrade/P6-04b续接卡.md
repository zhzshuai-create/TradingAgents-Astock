## 三、每日协议

- 单日 1 个，不并发；约 17–19 分钟、27–31 次调用、0.27–0.34M tokens，每天单独批准。
- 起服务：

```bash
ACTIVE_ANALYSIS_UI=next TA_ENABLE_REAL_RUNNER=1 \
  .venv/Scripts/python.exe scripts/run_backend.py --real-models --port 8600
```

- 创建任务：`POST /api/v1/jobs`，头 `Idempotency-Key: <uuid>`，请求体与 Canary 相同：

```json
{"ticker":"002138","analysis_date":"2026-11-06","config":{"llm_profile":"deepseek-default","parallel_analysts":true,"stage_toggles":{"policy":true,"hot_money":true,"lockup":true}}}
```

  - 轮询 `GET /api/v1/jobs/{job_id}`，只有到 `succeeded` / `failed` / `interrupted` / `cancelled` 才允许停机。
- 停机：只在终态后发 `CTRL_BREAK_EVENT`；图在跑时绝不发信号，宁可留着进程人工确认。正常停机 rc=0，8600 无监听。

## 五、已知坑

1. 停机信号发给子进程组，启动脚本自身也在同一控制台；脚本里不要重复发信号，也不要在创建失败时误停后端。
2. 收到信号后 API 先停、worker 继续跑图，主进程等 30 秒后退出。偏离这一点就是 11-08 的中断事故。
3. 中断任务的 `job_stages` 可能仍显示 `active`；以 `jobs.status` 为准。
4. 成功任务事件是 41 行（created 的 seq 为空 + seq 1..40），不是 40 行。
5. 调用数会浮动（27 / 31），判断重复看事件流，不看总次数。
6. 并行阶段的 `started_at == finished_at` 正常，看 `duration_ms`。
7. 数据源告警照旧：股东研究 `'dict' object has no attribute 'strip'`、CLS 新闻失败/超时、mootdx 走 sina 回退；只进记录，不在本票修。
8. 审计是只读的，但 SQLite 读 WAL 库会刷新 `jobs.db-shm` 读标记；`jobs.db` 与 `-wal` 字节不变。
9. 若临时写驱动脚本，放 `%TEMP%` 且不提交；要点就是三、里的创建与停机规则。
