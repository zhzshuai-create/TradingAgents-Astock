## 四、契约行为

依据：`contracts/core-wireframes.md` 第 4 节 W04、`contracts/interaction-checklist.md` M02/M03/M05/M07、`contracts/api-v1.md` 1.1/1.5/1.10、`contracts/semantic-dictionary.md`。

### 4.1 头部

- 股票名或代码（名称为 null 时回退代码，不编造）、分析日期、状态徽标。
- 状态文案只用 `lib/jobStatus.ts` 的 `JOB_STATUS_META`；`interrupted` 继续用 P2-07 起的「等待人工处理」，不要另写「执行中断」或「运行中」。
- 动作组只按服务端 `allowed_actions` 渲染，不在前端推状态表。P2-10 只是静态展示：按钮 `disabled`，不挂任何请求；P2-12 才接暂停/继续/取消/重试。
- `succeeded` 且 `report_id` 非空时显示「打开报告」主按钮，导航到 `/reports/:reportId`（P3 占位页）；`report_id` 为空时不渲染（WEB-14）。
- `allowed_actions` 为空时动作组整体不渲染（WEB-14）。

### 4.2 阶段总览

- `stages` 固定 12 项，顺序与 `index` 以服务端为准，不按前端数组位置猜。
- 桌面：`index <= 7` 的 7 个分析阶段一行，`index >= 8` 的 5 个流程阶段一行；每格显示序号、名称、状态。
- 当前阶段高亮：优先 `current_stage.id`；`current_stage` 为 null 但某个阶段是 `active` 时取该阶段；两者都没有就不高亮。
- 点击某阶段滚动到该阶段报告并展开；不要触发第二次详情请求。
- 状态文案：`pending`「等待中」、`active`「执行中」、`done`「已完成」、`failed`「失败」、`skipped`「已跳过」。`skipped` 不得写成失败或错误。
- 移动：12 行单列时间线，不出现两列及以上（M05）；当前阶段高亮。

### 4.3 统计条

- 字段来自 `stats`：`model_calls`、`tokens_in`、`tokens_out`、`elapsed_ms`。
- 未开始的任务四项都是 0，照实显示 0，不伪造「进行中」。
- 耗时复用 `frontend/src/features/jobs/format.ts` 的 `formatDuration`；Tokens 加千分位或按现有格式，保持一致。
- 统计只读，不轮询。

### 4.4 阶段报告

- 列表按 `index` 倒序，每个阶段一行；最近完成的阶段自动展开一次。
- 「最近完成」定义：`status` 为 `done` 或 `failed` 且 `finished_at` 非空的阶段里 `finished_at` 最大者；`finished_at` 相同取 `index` 较大者。没有完成阶段时不自动展开。
- 展开时才请求 `GET /api/v1/jobs/{jobId}/stages/{stageId}`；收起再展开可用缓存，不重复请求；切换任务后缓存不串。
- `pending`、`active`、`skipped` 不请求接口，直接显示「尚未产出」。即使请求返回 `markdown: null` 也显示「尚未产出」。
- 返回的 `markdown` 先用折叠预览显示前若干行（约 12 行或 1200 字符，二选一固定），再给「展开全文」；展开全文只展开已取回的内容，不再发请求。
- `truncated = true` 时在报告末尾显示「报告超过 128 KiB，仅显示前 128 KiB」，不编造剩余内容。
- `404 stage_not_found` 或阶段请求失败：只在该阶段行内给安全文案与「重试」，不影响详情页其他区域；不渲染响应体、堆栈或路径。
- Markdown 用契约指定的 `react-markdown`，必须开 `skipHtml`；外链用自定义 `a` 组件输出 `target="_blank" rel="noopener noreferrer"`。原始 `<script>`、`<iframe>`、事件属性一律不进入 DOM（WEB-11）。
- 任务失败或中断时，已完成阶段的报告仍可展开；这是契约 1.10 的明确行为。

### 4.5 状态说明区

- `failed`：显示 `error.message` 的安全文案（只取投影字段），给下一步说明；真实重试按钮属于 P2-12，本票不接。
- `interrupted`：说明「任务已中断，需要人工选择续跑或重新分析」，给「从检查点继续」入口的只读说明；不发请求。
- `pause_requested`：显示「正在暂停，将在当前阶段结束后生效」。
- `cancel_requested`：显示「正在取消，当前阶段结束后生效」。
- `queued`：显示「等待 Worker 认领」，不显示阶段进度。
- 其他状态不额外加说明，避免同一句话重复出现。

### 4.6 404 与错误

- `GET /jobs/{id}` 返回 404 `job_not_found`：显示「没有找到这个任务」，只给回任务列表（`/jobs`），不创建任务、不自动重试。
- 非 404 失败：保留当前路由，给安全错误文案与「重试」；不得渲染响应体或路径。
- `jobId` 为空或格式异常也走同一 404 页，不抛异常。

### 4.7 移动结构

- 阶段总览单列；统计条换行不溢出。
- 阶段报告用底部抽屉（现有 `Drawer` 只有 left/right，需要加 `side="bottom"` 变体），抽屉内独立滚动，页面不出现双层滚动；打开时锁页面滚动，关闭恢复。
- 阶段报告在移动端不内联展开，点击阶段行打开底部抽屉；桌面内联展开。
- 390 与 360 无页面级横向滚动（M07）；触控项不小于 44px（M03）。
- W04 的吸底主操作条属于 P2-12 的动作实现；本票不新造一个吸底按钮条，只保证现有只读动作组在 390/360 可达、不被底栏遮挡。

## 九、容易踩的坑

1. `JobDetail.stages` 的名称与顺序来自服务端；不要用前端硬编码的 12 个中文名覆盖，也不要把 `index` 当数组下标之外的排序依据。
2. `current_stage` 在阶段切换间隙可能为 null；此时用 `stage.status === "active"` 兜底，不伪造阶段号。
3. 最近完成的时间比较要用 `finished_at`，不要只看 `index`；没有完成阶段时不要自动展开任何行。
4. 自动展开会立即触发一次阶段报告请求；不要因为「展开状态初始化」重复请求两次（用受控的 `expandedId`，请求由展开状态驱动）。
5. `react-markdown` 默认不执行原始 HTML，但仍要显式 `skipHtml`；不要用 `dangerouslySetInnerHTML` 做自定义渲染。
6. `rel` 必须是 `"noopener noreferrer"` 两个词，只写 `noopener` 会被 WEB-11 抓到。
7. `succeeded` 但 `report_id` 为 null 时显示「报告不可用，请联系维护」一类安全说明，但不显示「打开报告」；不要伪造链接。
8. `failed` 的 `error.message` 已经是安全文案；仍需经 `displayErrorMessage` 或同等过滤，不要直接拼堆栈。
9. 404 判定用 `ApiError.status === 404` 或 `code === "job_not_found"`；`stage_not_found` 只影响单个阶段。
10. 移动断点只由 CSS 控制；jsdom 不执行媒体查询，底部抽屉与单列时间线由 E2E 覆盖。
11. 现有 `Drawer` 只有 left/right；补 `side="bottom"` 时要同步 `Drawer.module.css` 的定位、最大高度与安全区，不改 Dialog 的全屏行为。
12. 抽屉打开要锁 `body` 滚动，关闭恢复原值；不要用 `overflow: hidden` 写在页面容器上导致桌面也被锁。
13. 统计的 `elapsed_ms` 可能为 0；`formatDuration(0)` 当前返回「—」，这是列表的约定，详情是否沿用要在组件测试里固定，不要一票两套格式。
14. `scripts/seed_e2e_jobs.py` 必须 `TA_E2E=1` 才运行，并在检测到非临时库时拒绝执行；不要把它接进产品路径或常规测试。
15. 造九种状态优先走服务层已有方法（`request_pause` + `pause_at_boundary`、`request_cancel`、`finish_failure`、`mark_interrupted`、Worker 跑假图）；只有服务层无法表达的 running 中间态才用夹具 SQL，并确保 CHECK 约束与阶段行一致。
16. 阶段报告接口返回的 `markdown` 可能已经被 128 KiB 截断；`truncated` 为 true 时不要重复提示「展开全文」, 直接说明只显示前 128 KiB。
17. `react-markdown` 是新增依赖，必须改 `package.json` 与 `package-lock.json` 并跑 `npm ci` 验证；不要只改 lock 或只改 package。
18. E2E 的 `/api` 全部指向临时后端；不要用 Playwright 桩代替 E2E-05 的真实阶段报告读取，否则九状态与报告展开没有真实数据证据。
19. 阶段报告请求失败只影响单个阶段；不要因为一个阶段 500 把整页打成错误页。
20. `/jobs/:jobId` 的旧占位文案「将在 P4 接入」要删干净，避免与新页面并存。
