# 回滚手册：双栈灰度的八步退路

适用：P6 观察期（新版 `next` 写入者）出现下列任一情况时立即回滚。

触发条件（计划 8.8）：

- 同一任务出现重复模型执行；
- 报告字段丢失或 `content_hash` 漂移；
- 任务错误后自动重跑；
- 数据损坏（数据库打不开、行数异常减少、报告文件缺失）。

回滚目标：**回到旧版唯一写入者**，新版只保留只读入口；数据只在损坏时从备份还原。
本手册的每一步都给出命令、可观测断言、预计耗时与失败停点。任何一步断言不通过就停在该步，不要带着未确认的状态继续往下做。

## 零、回滚前先做一次备份（约 1 分钟）

```bash
.venv/Scripts/python.exe scripts/backup_restore.py backup --live
```

输出末行是 zip 的绝对路径，`[backup]` 行里有文件数与字节数。**把 zip 的 sha256 记进演练记录**，后面第 7 步只认这份包：

```bash
.venv/Scripts/python.exe -c "import hashlib,pathlib; p=pathlib.Path(r'<上一步的 zip>'); print(hashlib.sha256(p.read_bytes()).hexdigest())"
```

断言：命令退出码 0，且输出 `[backup] 校验通过`。
失败停点：备份失败时不要进入回滚；先解决磁盘/权限问题，否则第 7 步没有可用的还原包。

## 一、禁止新版创建任务（约 2 分钟）

P6-06 之前（没有 `scripts/stack_mode.py` 时）：

```bash
set ACTIVE_ANALYSIS_UI=legacy
# 重启 8600 后端（停掉当前进程后按原方式启动）
```

P6-06 之后：

```bash
.venv/Scripts/python.exe scripts/stack_mode.py set legacy
```

断言（二者满足其一即可）：

1. `GET /api/v1/meta/options` 返回的 `write_mode` 为 `"legacy"`；
2. 用一个新 `Idempotency-Key` 调 `POST /api/v1/jobs`，返回 `409 write_mode_legacy`。

同时旧版仍在：`http://127.0.0.1:8501/_stcore/health` 返回 `ok`。
失败停点：开关没生效说明后端没真正重启（变量只在启动时读一次）；先确认进程启动时间，不要继续。

## 二、等运行中的任务到终态或协作取消（5–30 分钟）

先只读列出未终态任务：

```bash
.venv/Scripts/python.exe -c "import sqlite3,pathlib; db=pathlib.Path.home()/'.tradingagents'/'jobs.db'; c=sqlite3.connect(db.as_uri()+'?mode=ro', uri=True); print(c.execute(\"select id,status from jobs where status not in ('succeeded','failed','cancelled')\").fetchall())"
```

有任务就二选一：

- 等它自然到终态（不打断正在跑的模型调用，避免半截报告）；
- 通过 `POST /api/v1/jobs/{id}/cancel` 协作取消。取消是请求，不是强杀；Worker 在下一个检查点退出。

断言：上面的查询返回空列表，或只剩 `cancelling` 且在 1 分钟内归零。
失败停点：取消后 10 分钟仍在推进 → 记录任务 id 与最后事件时间，按 Worker 租约问题单独处理，不要直接改库。

## 三、确认唯一写入者已切回旧版（约 3 分钟）

```bash
curl -s http://127.0.0.1:8600/api/v1/meta/options
```

断言：`write_mode` 为 `"legacy"`；旧版 8501 能列出并打开历史任务。
失败停点：`write_mode` 仍是 `"next"` → 回到第一步，检查环境变量与进程。

## 四、验证兼容投影仍可读（约 5 分钟）

新版报告的兼容投影 `legacy_projection` 默认开启，旧版读的是同一份投影，不需要迁移数据。

操作：在旧版打开最近一份新版任务报告；或调 `GET /api/v1/jobs/{id}/report`，确认 `sections` 非空。

断言：章节数量与回滚前记录的一致；报告 `content_hash` 与回滚前记录一致（字段漂移就是触发回滚的原因，回滚不负责修数据）。
失败停点：投影读不出来但数据库正常 → 保留现场，按第 7 步只还原数据副本并比对，不要先在真实目录上动文件。

## 五、保留新版只读入口（约 2 分钟）

后端继续以 `legacy` 模式运行，不做停机。

断言：任务列表、任务详情、报告阅读器、SSE 重连都能用；`POST /api/v1/jobs` 仍返回 `409 write_mode_legacy`。
失败停点：只读接口异常但旧版可用 → 允许停掉 8600，回滚结论不变（旧版是唯一写入者）。记录异常接口名。

## 六、迁移保持新增式，不降级（约 1 分钟）

```bash
.venv/Scripts/python.exe -m alembic -c backend/alembic.ini heads
```

断言：输出单头 `0007 (head)`；数据库 `alembic_version` 与之一致。

```bash
.venv/Scripts/python.exe -c "import sqlite3,pathlib; db=pathlib.Path.home()/'.tradingagents'/'jobs.db'; c=sqlite3.connect(db.as_uri()+'?mode=ro', uri=True); print(c.execute('select version_num from alembic_version').fetchall())"
```

失败停点：出现多头或版本对不上 → 停止，不要执行任何 `alembic downgrade`。回滚只回运行模式，不回数据库结构。

## 七、数据损坏时才恢复备份（副本 10 分钟；真实目录另计，需人工确认）

顺序不能反：**先在副本上演练，再决定是否动真实目录。**

1. 停掉会写数据目录的进程（8600；8501 若在跑也停），确认端口已关闭。
2. 副本演练。把数据目录复制到同盘另一位置，然后对副本 dry-run 和 apply：

```bash
.venv/Scripts/python.exe scripts/backup_restore.py restore <zip> --root <副本目录>
.venv/Scripts/python.exe scripts/backup_restore.py restore <zip> --root <副本目录> --apply
```

   断言：dry-run 退出码 0 且列出 new / replace / keep；`--apply` 输出 `[apply] 已还原 N 个文件，复核哈希一致`，退出码 0；副本库能打开，行数与 manifest 记录的报告行一致。
   失败停点：sha256 校验失败或提示文件被占用 → 不要碰真实目录；先查谁还开着数据库（第 5.5 节的占用探测会点名文件）。

3. 真实目录替换（**需人工确认**）。确认副本演练结论、确认后端全停后：

```bash
.venv/Scripts/python.exe scripts/backup_restore.py restore <zip> --live --apply
```

   脚本会先对每个将被覆盖的文件做改名探测，被占用就整体拒绝、不改任何文件；通过后把旧文件移入 `~/.tradingagents/pre-restore-<时间戳>/`，再按文件替换，最后复核哈希。
   断言：输出 `[OK]`；`pre-restore-*` 目录里能找回旧 `jobs.db` 与旧 `report` 文件；启动后端后任务列表与报告可读。
   失败停点：任何一步报 `[FAIL]` → 目标文件未被替换或已保留在 `pre-restore-*`，按提示处理后重试，不要手工删 `pre-restore-*`。

4. `jobs.db-wal` / `jobs.db-shm` 会被一并移入 `pre-restore-*`，不再放回。还原后由后端重新生成。

## 八、不触碰交易日志（约 3 分钟）

回滚全程不读写 `trade-journal`（8502）的数据，也不合并其数据库；本仓库脚本不 import `web.*`，不调用 8502。

断言：

- 8502 进程仍在（若回滚前在跑），`http://127.0.0.1:8502/_stcore/health` 返回 `ok`；
- 交易日志数据目录的文件清单与回滚前一致；
- 新版日志页仍按 P5 口径处理三种不可用状态，不自动拉起进程。

失败停点：交易日志出现写入或健康异常 → 立即停手，属于另一仓库的问题，不在本手册范围。

## 九、演练记录模板

| 项 | 内容 |
| --- | --- |
| 日期 / 执行人 | |
| 触发原因 | 重复执行 / 字段丢失 / 自动重跑 / 数据损坏 |
| 回滚前备份 zip | 路径 + sha256 |
| 第 1–6 步断言 | 逐项 PASS / FAIL |
| 第 7 步副本演练 | 还原文件数、字节、哈希一致与否 |
| 第 7 步真实替换 | 需人工确认：确认人、时间、`pre-restore-*` 路径 |
| 第 8 步交易日志 | 未触碰证据（清单一致） |
| 结论 | 回滚成功 / 停在哪一步 / 待办 |

耗时合计：不还原数据约 15 分钟；含副本演练与真实还原约 40 分钟（不含等待运行任务到终态的 5–30 分钟）。
