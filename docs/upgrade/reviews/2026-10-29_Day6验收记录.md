## 2. 确定性证据

同一输入连续运行 10 次，把事件、任务详情、报告一起序列化后取 SHA-256：10 次完全相同，唯一摘要 `2ff35f03…6d43ba`。

正常路径 S00 的固定输出：

| 项 | 值 |
| --- | --- |
| 事件总数 | 40 |
| 阶段事件 | 24（12 开始 + 12 结束） |
| 统计事件 | 13 |
| 状态转换 | 2（queued→running→succeeded） |
| 报告事件 | 1 |
| 模型调用 | 14 |
| 输入 Token | 182430 |
| 输出 Token | 41208 |
| 报告生成时间 | `2026-10-24T15:30:00+08:00` |
| 报告内容哈希 | `869ee791…87f3a6202`，与黄金样本逐字段相等 |

实现约束：

- 时间只来自虚拟时钟，起点 `2026-10-24 09:30:00 +08:00`，12 阶段各 30 分钟。
- 不调用 `sleep`，不用 `random`，不读系统时间。
- 报告 ID 由 `uuid5` 从 job id 派生；黄金样本保留固定 ID。
- 报告只存在内存，不写盘。

## 6. 演练发现的契约缺口

提交：`7cc8ed9 docs: Day 6 契约缺口回写——T20、审计记录与幂等第 3 步`

| 编号 | 缺口 | 怎么发现 | 回写 |
| --- | --- | --- | --- |
| G8 | `paused` 上取消无合法路径：直接取消被 I11 拒绝，恢复又不是取消 | 构造 S03 时状态机走不通 | 新增 T20 `paused → cancel_requested`；SM-14；错误字典补说明 |
| G9 | 审计记录与 SSE 序号混用：`created`、`transition_rejected`、`reconcile_note` 若占 `seq`，补发会出现空洞 | 构造 B3 时发现备注无处安放 | SSE 契约明确审计记录不占 `seq` 不广播；崩溃边界 B1、B3、B4 同步改口 |
| G10 | 对账备注没有字段承载 | B3、B4 的备注只能口口相传 | `JobDetail` 增可选 `reconcile_notes`，元素 `{code, message, at}` |
| G11 | 幂等第 3 步原文只写「无幂等键」，与第 4 节 20 并发裁决矛盾 | 写账本时十个不同键会产生十个任务 | 第 3 步改为「幂等键未命中（未携带或首次出现）」并补理由 |

另修一处示例错误：`report_ready.content_hash` 原示例带 `sha256:` 前缀，与 ReportDTO 的 64 位十六进制不一致，已改。
