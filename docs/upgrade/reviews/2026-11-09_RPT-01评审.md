# RPT-01 评审：新报告冻结图表输入

结论：达标。假 provider 的三条出口全对上；DeepSeek 真实任务在修复一个 P4-01 遗留的 K 线迭代缺陷后，跑出 `reports.chart_snapshot_status = frozen`，sidecar 的 `report_content_hash` 与行内 `content_hash` 完全一致。两个本地提交（`bc84a5f` 功能、`c7772d0` 修复），未推送。

## 一、改了什么

**采集。** [`StockService.chart_inputs`](file:///C:/Users/zhzsh/TradingAgents-astock/backend/app/services/stock_service.py#L71) 只取两块：`stock:snapshot:quote` 与 `stock:kline`（`day`，120 根），用现有缓存端点与 TTL，合并成一个多块信封。不新增 endpoint id，`STALE_AFTER` 未动。

**快照结构。** 新文件 [`chart_snapshot.py`](file:///C:/Users/zhzsh/TradingAgents-astock/backend/app/services/chart_snapshot.py#L38) 产出 `chart-snapshot-v1` 文档：`schema_version/ticker/captured_at/report_content_hash/status/reason/blocks`，`blocks` 内每块保留 `status/source/as_of/fetched_at/data`。状态判定只有一条：[`_failure_reason`](file:///C:/Users/zhzsh/TradingAgents-astock/backend/app/services/chart_snapshot.py#L84) 按 quote、kline 顺序找第一个失败块。超过 512 KiB 抛 `ChartSnapshotOversize`，worker 记异常并且不落盘。

**存取。** [`ReportStore.write_chart_snapshot`](file:///C:/Users/zhzsh/TradingAgents-astock/backend/app/services/report_store.py#L136) 与 `report.json` 同款 `tmp` + `os.replace`；[`read_chart_snapshot`](file:///C:/Users/zhzsh/TradingAgents-astock/backend/app/services/report_store.py#L154) 只接受 `schema_version=chart-snapshot-v1`、`ticker`、`blocks` 三件齐全的文档，损坏或缺件返回 `None`。

**Worker。** 构造参数新增 `chart_snapshotter=None`。[`_capture_chart_snapshot`](file:///C:/Users/zhzsh/TradingAgents-astock/backend/app/worker/main.py#L347) 的顺序是：用最终 sections 算 `content_hash` → 抓取 → 写文件 → 返回状态。抓取异常、`OSError`、心跳丢失、无快照器都返回 `none`。T03、T07（`pause_noop`）、T14（`cancel_noop`）三条成功路径都在 `_publish_report` 之前调用同一个函数，再把结果传给终态事务。

**终态事务。** [`finish_success`](file:///C:/Users/zhzsh/TradingAgents-astock/backend/app/services/job_service.py#L936) 新增关键字参数 `chart_snapshot_status=None`。为 `None` 时完全保持现状；非 `None` 时校验枚举、非法值按 `none`，然后浅拷贝报告并覆盖 `meta`，不改调用方对象。数据库列、CHECK 约束、`finalize_report`、`report_ready` 载荷都没动。

**接线与开关。** [`build_chart_snapshotter`](file:///C:/Users/zhzsh/TradingAgents-astock/scripts/run_backend.py#L132) 默认返回真实实现，`TA_CHART_SNAPSHOT=0` 返回 `None`；`run_backend` 现在把同一份 `DefaultMarketProviders` 与 `MarketCache` 同时给 API 和快照器，命中缓存的概率与股票页一致。`e2e/e2e_p6.py` 的隔离环境显式写 `TA_CHART_SNAPSHOT=0`，离线 e2e 不会走到供应商超时。

**前端。** [`CHART_SNAPSHOT_LABELS`](file:///C:/Users/zhzsh/TradingAgents-astock/frontend/src/features/reports/format.ts#L36) 三个中文标签，[`ReportMeta`](file:///C:/Users/zhzsh/TradingAgents-astock/frontend/src/features/reports/ReportMeta.tsx#L40) 在「数据质量」下方加一行只读 `图表快照`，`data-testid="meta-chart-snapshot"`。列表、导出、`api/types.ts` 未改。

**追加修复（真实跑暴露，单独提交 `c7772d0`）。** 第一次 DeepSeek 任务回落 `kline_error`，追到 P4-01 的 [`DefaultMarketProviders.kline`](file:///C:/Users/zhzsh/TradingAgents-astock/backend/app/services/market_providers.py#L386)：`for row in frame` 在 pandas DataFrame 上迭代的是列名，写日期时抛 `TypeError: string indices must be integers`。mootdx 无数据后 sina 兜底已返回 800 行，所以这不是网络问题。改为 `frame.to_dict("records")`，并补一条离线回归（mootdx 空 + sina 两行）。bar 字段、单位、`source` 标注与 `/stocks/{code}/kline` 契约都不变。
