## 二、逐项根因与修法

1. **ruff 10 项**：未使用导入/变量、空 f-string、重复字典键。全部删除或改正，`ruff check .` 通过。
2. **测试依赖装不齐**：CI 改为 `pip install -e ".[backend]" -c constraints.txt pytest httpx`。`pip check` 同时通过。
3. **没有前端作业**：新增 `npm ci` → `npm run build` → `npm run check:bundle` → `npm test`。
4. **前端时区**：在 `frontend/vite.config.ts` 的 `test.env` 固定 `TZ=Asia/Shanghai`。测试数据带 `+08:00`，断言读北京时间；runner 默认 UTC 必然差 8 小时。用 `TZ=UTC npx vitest run` 复现：修前 3 失败 / 536 通过，修后 539 全过。
5. **测试依赖本地 `.venv`**：`e2e_p5.main` 和 `stack_launch.main` 会检查仓库 `.venv`，CI 把包装进系统解释器，没有 `.venv`。修法是测试注入当前解释器：
   - `tests/backend/test_p6_exit.py`：`_stub_p5` 把 `e2e_p5.PYTHON` 指向 `sys.executable`。
   - `tests/backend/test_stack_launch.py`：守卫用例改用 `sys.executable`；SL-06 额外 patch `launch.VENV_PY`。
   生产脚本的守卫逻辑没有放宽。
6. **Ubuntu 无中文字体**：7 条 PDF 用例报 `PdfFontMissing`（`test_pdf_renderer` 4 条、`test_p3_exit` 1 条、`test_exports` 2 条，其中 exp08 是导出失败的连带）。CI 在 Linux 上装 `fonts-wqy-zenhei`。

## 三、怎么定位到字体

匿名账号读不到 Actions 日志：`GET /actions/jobs/{id}/logs` 返回 403 `Must have admin rights to Repository`。于是把 pytest 失败转成公开可读的 check-run 注解。

第一次（`7187e48`）注解数为 0。原因不是命令写错，而是 runner 的 bash 默认 `-e`：pytest 非零后脚本立即退出，失败分支从未执行。`6a98b65` 在 pytest 前加 `set +e`，下一轮 `42591140700` 的注解直接列出 7 条 `PdfFontMissing`。

这条诊断链路保留在 CI 里：失败时输出 `pytest-exit`、每条 `FAILED`、日志尾部 30 行，并写作业摘要。以后再遇到平台差异，不必再借管理员权限。
