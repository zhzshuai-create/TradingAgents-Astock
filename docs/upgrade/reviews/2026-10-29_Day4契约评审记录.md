## 2. 本次定死、后续不要回改的口径

1. 状态枚举只有四个（`ok / empty / error / stale`），部分成功用 `partial` 布尔加 `failed_blocks` 表达，不加第五个状态。
2. `is_stale` 恒等于 `status == "stale"`；`empty` 与 `error` 时 `data` 与 `as_of` 必须为 null。
3. 数据源失败用 HTTP 200 + 信封；请求不合法、对象不存在、状态冲突用 4xx/5xx。两者不互相顶替。
4. 数据源错误码只有四个：`upstream_timeout`、`upstream_error`、`upstream_rate_limited`、`data_parse_error`。
5. P0 未实现的市场接口返回 501 `not_implemented`，不用 404 冒充，也不返回假数据。
6. 任务按钮只按 `allowed_actions` 渲染；前端不自己推状态表。
7. 多区块接口的顶层 `as_of` 取主区块（快照 `quote`、概览 `indices`），逐块时间留在 `blocks`。
8. SSE 序号在同一任务内连续；对账补发的事件分配新序号追加在尾部，不插历史。
9. `retry` 与 `resume_from_checkpoint` 都创建新任务，原任务字段不变；暂停后的「继续」不是新任务。

## 3. 计划外新增与理由

| 新增 | 理由 |
| --- | --- |
| `market_ok.json` | 交付清单只列了三份异常样本，但 6.4 要求「分别准备正常、空、失败和陈旧样本」，缺正常态无法证明四态互斥 |
| `market_partial.json` | 验收要求「部分成功不能用一个总状态掩盖」，没有样本就无法测试这条 |
| `GET /exports/{id}` 与 `/file` | PDF 生成是异步的，只给 POST 没有查询与下载入口，前端拿不到文件 |
| `GET /meta/options` | 启动器的模型档位与阶段开关是服务端白名单，前端需要一份枚举，不能硬编码服务端配置 |
| 顶层 `partial` 与 `failed_blocks` | 在四态不变的前提下表达部分成功，避免新增第五种 status |

## 4. 需要用户拍板的五件事

1. 字段命名：全链路沿用 `snake_case`（对齐 `report-schema-v1`），前端不做 camelCase 转换。若要改成 camelCase，越早越便宜。
2. PDF 导出做成异步加两个补充接口，而不是同步阻塞返回文件。
3. `GET /meta/options` 是否保留；如果前端愿意把档位写死，可以删掉它。
4. P0 阶段市场页面对 501 的展示口径：显示「建设中」并保留旧版入口，还是直接隐藏这些页面。
5. 单用户无鉴权只适用于本机运行；若之后要多人访问，401 与登录需要在 P1 之前加。
