## 3. 口径说明

### 3.1 判据 1 的唯一例外：`sec-plan` 的两行头

旧版 `web/components/report_viewer.py` 用 `extract_signal()` 扫描 `investment_plan` 等正文字段找 BUY/SELL/HOLD，决策卡也从正文取评级；DTO 的 `meta.rating` / `meta.signal` 不进旧版接口。反投影因此只在 `sec-plan` 正文前加两行：

```
**Rating**: Overweight

**Signal**: Buy
```

这两行是旧版徽标与决策卡能显示正确结论的唯一来源，属于兼容层的必要投影，不是 DTO 内容。往返测试在比较 `sec-plan` 前剥掉这两行及其后的空行，其余 12 章与 `sec-plan` 剩下部分逐字节相等；新前端与三端渲染完全不读这两行。

### 3.2 T17 与 `chart_snapshot_status`（C3 冲突）

backlog C3 已定稿：旧报告的报告行永远是 `chart_snapshot_status = none`；「补数」只标在导出产物上（补数时间与「导出时补充数据」字样），不伪装成原分析快照，也不新增契约字段。`test_t17_legacy_export_carries_supplement_time` 按此验收。本票不改变该口径。

### 3.3 R-01 打开阅读器的桩缺陷（测试代码修正，非产品改动）

`e2e/reports_e2e.py` 的列表桩注册的是 `**/api/v1/reports**`。Playwright 的通配符 `**` 跨路径段，这条路由同时命中详情 URL `/api/v1/reports/r-many-05`，于是阅读器拿到的是列表 JSON，`detail.meta` 为 undefined，`page-report-detail` 渲染成空 `<section>`。原用例只等这个 section 可见：若 Playwright 首次采样落在加载骨架期间，用例通过；若详情请求先返回，section 变空，等待 30 秒后超时。P3-04 起它一直是这种偶发状态，本次全量复跑第一次触发失败。

修正只动测试桩：最后注册单段路由 `**/api/v1/reports/*`，按 `report_id` 返回 `meta + sec-decision` 的最小合法 DTO；同时新增一条 `reader-header` 可见断言，防止再靠骨架通过。R-01 从 67 增至 68 checks，产品代码、接口与契约均未改。

### 3.4 投影失败未实现 UI 警告（D6）

按 backlog D6：冻结的 API 与 ReportDTO 都没有投影状态字段，P3 只做「失败写服务端日志」，界面不提示；本票如实记录为未实现 UI 警告，留待 P6 双栈阶段或按 `FREEZE-v1.md` 第 4 节解冻后再做。投影失败的隔离与日志由 P3-08 的 `test_legacy_projection.py` 与 R-08 覆盖。
