## 八、容易踩的坑

1. 移动端主按钮只能渲染一份。头部与吸底条同时渲染 `stock-primary-action` 会让 Playwright 严格模式报两个元素，也会出现双主操作；判定放在 `StockPage`，头部只收 `mobile`。
2. 吸底条底边必须严格是 `56px + safe-area`，不是 `56px`；E2E 断言 `bar.y + bar.height == viewportHeight - 56`（两档视口实测 788/744 恰好相等）。
3. 吸底条会压住内容，`.page` 必须补同高 padding-bottom；不补时最后一个估值卡或图表落在条下面。
4. 页签横滑要真实存在：五页签合计 456px，390 与 360 都会溢出；若为省事把 `min-width` 调小，W07M-01 会假过或恒过。
5. K 线移动端不能只靠 CSS 关手势：wheel 监听是原生 `addEventListener`，必须在 `mobile` 时直接不挂；触控 pointerdown 本来就被忽略，但 pointermove 还会动十字光标，属可接受行为。
6. 图表提示文案与 `data-mobile` 断言绑在一起；改文案要同时改 `StockPage.mobile.test.tsx` 与 `stock_e2e.py`。
7. 移动端按钮 44px 来自 `Button.module.css` 的 `@media (max-width: 767px) { min-height: 44px }`，不要再给单个按钮写死 `height`，否则 height 与 min-height 打架。
8. 首轮 390 曾出现 `aria-pressed` 读取早于 React 提交（URL 已改、渲染未完成）；读状态前用 `wait_for_function`，不要改成 sleep。
9. 同一条 `stock_e2e.py` 既跑桌面又跑移动：新增移动 flow 时不要动桌面 `main_flow` 的断言，否则 R-12/R-13 的 checks 基数会变。
10. `e2e_p3.py` 会改写 `reviews/2026-11-06_P3-09性能结果.json`，跑完必须 `git checkout --` 还原；`check_bundle.mjs` 必须 `--out` 到临时文件。
11. 截图目录 `ui_shots_p4/*` 被 `.gitignore` 覆盖，只作人工核对，不要 `git add -f`。
12. `useIsMobile` 在 `features/market/`；股票页跨 feature 引用与现有 `envelopeState`/`copy` 的用法一致。若 P4-11 要在 `lib/` 写 hook，不要再复制一份 matchMedia 逻辑。
