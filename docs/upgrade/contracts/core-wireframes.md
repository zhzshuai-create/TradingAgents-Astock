## 1. W01 工作台首页

目标：打开就有事可做。活动任务优先展示，其次是「分析一只股票」，最后才是市场与历史。

桌面结构（自上而下）：

1. 活动任务条：`贵州茅台 000629 · 多空辩论 9/12 · 查看`，右侧「还有 1 个」。
2. 主操作区：大搜索框「输入股票代码或名称」+ 主按钮「开始分析」。搜索有结果时下拉列出前 10 条，选中后直接进启动器，不在首页创建任务。
3. 今日市场摘要：三大指数四张卡；行业涨幅前 5 与强势股前 5 两列，点击钻进 W08 或 W07。
4. 最近任务：3 行，状态徽标 + 当前阶段 + 相对时间，点击进 W04。
5. 最近报告：3 行，评级徽标 + 股票 + 日期，点击进 W06。

移动结构：

1. 标题「工作台」+ 搜索图标。
2. 活动任务卡（整卡可点）。
3. 主按钮「分析一只股票」固定在首屏，不藏在菜单里。
4. 指数卡横向滚动，一屏两张半。
5. 最近任务 3 条；最近报告收起为「查看全部」。
6. 底部五导航，当前项高亮。

状态：

| 状态 | 表现 |
| --- | --- |
| 无活动任务 | 不显示任务条，主操作上移，不留空白 |
| 市场概览 stale | 指数卡右上角标「数据延迟」，显示 `as_of` |
| 市场概览 error | 摘要区显示「市场数据暂不可用」+ 重试，不影响发起分析 |
| 无最近任务/报告 | 空态文案 + 「开始第一次分析」按钮 |
| 搜索无结果 | 下拉显示「没有找到，检查代码或名称」 |

## 2. W02 统一分析启动器

形态：桌面居中对话框，移动全屏抽屉。不是独立路由，深链接为 `/workbench?launch=1&ticker=000629`。

内容顺序：

1. 标的：搜索框 + 已选中的「名称 代码」，可换票。中文名多命中时列出候选，不做自动选择。
2. 分析日期：默认取 `meta/options.default_analysis_date`，可改，不晚于服务器当天。
3. 配置：模型配置下拉（`llm_profiles`）、并行分析开关、阶段开关（默认收起，展开后 7 个分析阶段可关）。
4. 费用提示：一句「分析会调用付费模型，预计 5–15 分钟」，不显示编造的价格。
5. 主按钮「开始分析」，次按钮「取消」。

提交中的界面规则：

- 点击后按钮立即禁用并显示「提交中」，防重复点击。
- 返回 201：跳 `/jobs/:jobId`。
- 返回 200 且带 `X-Existing-Job`：跳该已有任务，提示「已有一个相同分析」。
- 返回 409 `active_conflict`：弹内联提示，给「查看进行中的任务」和「取消」，不提供强制新建。
- 返回 422：字段级错误留在表单内，不清空已填内容。
- 返回 429：显示 `retry_after_ms` 折算的等待秒数。

移动：单列，主按钮吸底；阶段开关用全屏二级页，避免小屏嵌套滚动。

## 3. W03 任务列表

桌面结构：

1. 筛选行：状态多选（九态，默认全选）、股票代码、日期范围（按分析日期）、「只看活动任务」开关、重置。
2. 表格列：股票（名称+代码）、分析日期、状态、当前阶段、耗时、创建时间、操作（查看）。
3. 活动任务的当前阶段带进度条；失败行在状态列显示错误码的安全文案。
4. 底部「加载更多」，无数据时显示空态。

移动结构：

- 表格换成摘要卡片：第一行股票名+状态徽标，第二行日期+阶段，第三行耗时。
- 筛选收进顶部「筛选」按钮，打开全屏筛选页，应用后在标题下显示已选条件 chips。
- 卡片整张可点，不做行内按钮。

状态：默认空列表、筛选后为空（给「清空筛选」）、接口错误（给重试，保留筛选）、加载更多失败（保留已加载项）。

依赖：`GET /jobs?status=&ticker=&date_from=&date_to=&active=&limit=&cursor=`。

## 4. W04 任务详情

桌面结构：

1. 头部：股票名+代码、分析日期、状态徽标、`allowed_actions` 渲染的按钮组（暂停/继续/取消/重试/从检查点继续/重新分析）。
2. 阶段总览：12 个阶段分两组——7 个分析阶段一行，5 个流程阶段一行；每格显示序号、名称、状态；当前阶段高亮；点击滚动到该阶段报告。
3. 统计条：模型调用、输入 Tokens、输出 Tokens、耗时。
4. 阶段报告区：按阶段倒序，最近完成的自动展开；展开时请求阶段报告接口，显示前若干行 + 「展开全文」；未完成阶段显示「尚未产出」。
5. 异常区：失败时显示 `error.message` + 下一步按钮；中断时显示「从检查点继续」与说明；暂停受理中显示「正在暂停，将在当前阶段结束后生效」。
6. 成功时头部下方出现「打开报告」主按钮。

移动结构：

- 阶段总览改为单列时间线，12 行纵向排列，不压成多列。
- 头部按钮收进「更多」菜单，主操作（取消/继续/打开报告）吸底。
- 阶段报告用底部抽屉，抽屉内单独滚动，页面本身不出现双层滚动。
- SSE 断线时顶部黄条「正在重连，阶段可能延迟」，重连成功自动消失；410 时黄条换成「刷新以恢复」并给刷新按钮。

状态必须逐一见到的：queued、running、pause_requested、paused、cancel_requested、cancelled、succeeded、failed、interrupted，以及 SSE 重连中/已过期、任务 ID 无效（404，按禁用词规则措辞）。

依赖：`GET /jobs/{id}`、`GET /jobs/{id}/stages/{stageId}`、`POST /jobs/{id}/actions`、`POST /jobs/{id}/retry`、`GET /jobs/{id}/events`。

## 5. W05 报告库

桌面结构：

1. 筛选行：股票代码、日期范围（按分析日期）、评级多选（五档 + unknown）。
2. 列表行：评级徽标、股票名+代码、分析日期、来源（AI 分析/历史导入）、生成时间（未知时显示「生成时间未知」）、信号、摘要是否有。
3. 排序固定生成时间倒序，未知时间的旧报告排最后。
4. 底部加载更多。

移动：行换卡片，评级徽标放左上，日期与来源放第二行；筛选进全屏页。

状态：空库、筛选为空、接口错误、旧报告缺生成时间、`origin = legacy_import` 的说明角标。

依赖：`GET /reports?ticker=&date_from=&date_to=&rating=&limit=&cursor=`。

## 6. W06 报告阅读器

桌面结构：

1. 顶栏：返回（还原来路筛选）、股票名+代码+日期、评级徽标、操作「导出 PDF」「重新分析」。
2. 左栏：13 个固定章节的目录，当前章节高亮，点击跳转并更新 `#sec-xxx`。
3. 中栏：报告正文，按清洗后的 markdown 渲染，禁用原始 HTML；表格过宽时容器内横向滚动。
4. 右栏：决策卡（评级、信号、目标价、止损参考、时间跨度）、数据质量状态、来源任务链接。
5. 导出：点击后按钮变进度态（排队/渲染/完成），完成后给下载按钮；失败给重试与错误文案。

移动结构：

- 单栏正文；目录改为抽屉，按钮固定在顶栏。
- 决策卡折叠在正文上方，默认收起一行摘要。
- 底部吸底操作条：导出 PDF、重新分析。
- 章节跳转后抽屉自动关闭，滚动位置落在章节标题。

状态：正文加载中、报告不存在、章节缺失（停在顶部不报错）、导出四态、历史报告无图表快照、正文含外部链接（新窗口打开并加 `rel="noopener"`）。

依赖：`GET /reports/{id}`、`GET /reports/{id}/markdown`、`POST /reports/{id}/exports/pdf`、`GET /exports/{id}`、`GET /exports/{id}/file`。

重新分析的配置来源固定为：报告有 `job_id` 时对该任务执行 `retry / same_config`；`job_id` 为 null 的历史报告打开启动器并预填股票与分析日期。

## 7. W07 股票工作区

桌面结构：

1. 头部：股票名+代码、市场、现价与涨跌幅、数据时间；主按钮「分析这只股票」打开启动器并预填。
2. 页签：估值、K 线、分时、新闻、报告、任务。
3. 估值：一致预期 EPS、动态 PE、PEG、消化估值年数；任一缺失显示「—」并注明不可得，不显示 0。
4. K 线：周期切换日/周/月，图内缩放，不复权标注。
5. 分时：日期选择默认最近交易日；午休断线；历史超保留期显示 empty 文案。
6. 新闻：纯文本列表，标题、来源、时间；外链新窗口。
7. 报告/任务：各自跳转报告库与任务列表并带 `ticker` 筛选。

移动：页签横向滚动，图表容器内部横向滚动，页面本身不得横向滚动；「分析」按钮吸底。

状态：ticker 解析失败 400 页、快照部分失败（`failed_blocks` 标出哪块不可用）、stale 横幅带 `stale_reason` 文案、空数据、数据源错误。

依赖：`GET /stocks/{ticker}/snapshot|kline|intraday|news|reports`、`GET /market/search`。

## 8. W08 市场与钻取

桌面结构：

1. 市场状态条：`market_session` 的中文文案 + 最近更新时间。
2. 指数区：三大指数卡片。
3. 行业区：涨幅前 20 与末位若干，列排名、行业、涨跌幅、上涨/下跌家数、领涨股。点击行业行在右侧抽屉展开行业成分股（前 10），点成分股进 W07。

移动：指数横滑，行业与强势股用卡片；行业成分股用全屏二级页；页面级不得横向滚动。

## 9. W09 交易日志不可用

定位：独立应用（默认 `http://127.0.0.1:8502`），以 iframe 嵌入。本系统不读写它的数据。

可用时：整页 iframe，顶部一行「日志服务运行中」与「新窗口打开」。

不可用时（本线框重点）：

1. 说明句：「交易日志是独立应用，当前没有在运行。」
2. 原因按 `journal.reason` 分支：
   - `not_running`：给启动命令 `run.bat` 与「重试」按钮。
   - `not_installed`：给目录缺失说明与安装指引，不显示启动命令。
   - `probe_failed`：提示端口被其他服务占用，给检查步骤。
3. 「重试」重新请求 `meta/options`，不刷新整页。
4. 声明数据隔离：「本系统不会读取或修改交易日志的数据。」

依赖：`GET /meta/options` 的 `journal` 字段。

## 10. W10 设置页

分组：基本信息、模型、数据源、关于。P0 只把基本信息做实，其余显示「P1 开放」。

基本信息：

- 服务状态：接口可达、SSE 可达（用最近一次连接结果）。
- 版本：`app_version`、`contract_version`。
- 服务器时间：`server_time`，标注时区。
- 交易日志：可用/不可用，链接到 W09。
- 数据源：P0 只显示当前数据源名称与最近成功时间，不做开关。

关于：许可与免责声明入口，版本号与构建时间。

移动：分组列表，点进二级页；`#group-xxx` 可深链接。

依赖：`GET /meta/options`。
