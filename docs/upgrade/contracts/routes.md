## 2. 全局规则

1. **活动任务条**：有活动任务时，所有页面顶部常驻一条「当前阶段 + 进度 + 查看」；点击进 `/jobs/:jobId`。没有活动任务时不占位。多个活动任务时显示最近创建的一个，并给「还有 1 个」的入口。
2. **返回不清筛选**：从 `/jobs` 进详情再返回，状态多选、股票、日期范围必须原样恢复；从 `/reports` 进阅读器再返回同理。实现上用 `history.back()` 优先，直接打开时用 query 重建。
3. **深链接必须可刷新**：任何页面刷新后不得丢失身份（ticker、jobId、reportId、筛选、tab、章节）。
4. **未知路由**：给 404 页，两个出口——回工作台、回任务列表；不自动跳转。
5. **非法 ticker**：`/stocks/abc` 这类解析不到的路径给 400 页，文案「没有这只股票」，给搜索框与回市场；不静默改写到别的票。
6. **不存在的 job/report**：404 页，文案分别是「没有找到这个任务」「没有找到这份报告」，只给返回列表；**不创建、不自动补**（对应 `idempotency-conflicts.md` 第 2 节）。
7. **移动底部导航**五个：工作台、市场、任务、报告、更多（更多里放日志与设置）。桌面用顶部导航，二者路由完全一致。
8. **报告章节深链接**：`/reports/:id#sec-decision` 直接滚到该章；章节不存在时停在顶部，不报错。
9. **不把状态写进路径**：路径只含身份（ticker、jobId、reportId），筛选与 tab 走 query。这样同一份报告可以被两条不同筛选路径引用而不产生两套 URL。
10. **刷新恢复的优先级**：query > 本地记忆 > 服务端默认。三者冲突时以 query 为准。

## 3. 页面之间的主链路

```text
/workbench
  ├─ 搜索股票 → /stocks/:ticker（未创建任务时只读看盘）
  ├─ 点「开始分析」→ 创建任务 → /jobs/:jobId
  └─ 最近任务 → /jobs/:jobId

/market
  ├─ 行业行 → /stocks/:ticker?tab=valuation
  ├─ 强势股行 → /stocks/:ticker
  └─ 快讯 → 原文链接（外链，新窗口）

/jobs → /jobs/:jobId
  ├─ 已完成的报告 → /reports/:reportId
  ├─ 运行中 → 停在详情看阶段
  └─ 中断 → 「从检查点继续」创建新任务 → /jobs/:newId

/reports → /reports/:reportId
  ├─ 「重新分析」→ 创建新任务 → /jobs/:newId
  └─ 「导出 PDF」→ 停在阅读器，右下角显示导出进度
```
