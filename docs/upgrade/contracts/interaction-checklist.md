## 1. 十四条主线走查

### A01 搜索股票并创建分析

| 项 | 内容 |
| --- | --- |
| 入口 | `/workbench` 搜索框 |
| 操作 | 输入「宁德」→ 选中「宁德时代 300750」→ 启动器预填 → 日期用默认值 → 点「开始分析」 |
| 预期界面 | 搜索下拉只列股票；启动器显示名称+代码；主按钮变「提交中」并禁用；成功后跳 `/jobs/:jobId` |
| 预期接口 | `GET /market/search` → `GET /meta/options` → `POST /jobs`（新 UUID 幂等键）→ 201 |
| 预期事件 | `snapshot` → `status_changed(queued→running)` |
| 断言点 | 任务数 +1；响应 201；URL 换成新 jobId；没有重复 job |
| 失败分支 | 解析失败 422 `ticker_unresolved`；多候选 422 `ticker_ambiguous` 列候选；日期非法 422 `invalid_date` |

### A02 重复点击提交

| 项 | 内容 |
| --- | --- |
| 入口 | A01 的启动器 |
| 操作 | 提交后立刻再点两次（或网络慢时连点） |
| 预期界面 | 首次点击后按钮禁用，显示「提交中」；不出现第二个成功跳转 |
| 预期接口 | 同一 `Idempotency-Key` 的重放返回 200，响应头 `Idempotency-Replayed: 1` |
| 断言点 | 任务数只 +1；两次响应 job_id 相同；不产生第二条事件流 |
| 失败分支 | 若重放体不同，409 `idempotency_mismatch`，界面提示刷新后重试 |

### A03 已有相同活动任务

| 项 | 内容 |
| --- | --- |
| 入口 | 启动器，同票同日再提交 |
| 操作 | 配置相同提交一次；改阶段开关后再提交一次 |
| 预期界面 | 配置相同：跳已有任务并提示「已有一个相同分析」；配置不同：内联提示冲突，给「查看进行中的任务」与「取消」，不提供强制新建 |
| 预期接口 | 同配置 200 + `X-Existing-Job`；不同配置 409 `active_conflict` + `details.active_job_id` |
| 断言点 | 两次都没有创建新 job；冲突提示里的 job id 可直接打开 |
| 失败分支 | 活动任务刚好结束：重试提交成功，界面不再显示冲突 |

### A04 跨页查看任务

| 项 | 内容 |
| --- | --- |
| 入口 | `/market`、`/reports`、`/stocks/:ticker` 顶部活动任务条 |
| 操作 | 从不同页面点任务条进 `/jobs/:jobId`，再返回 |
| 预期界面 | 所有页面都有任务条；点进去是同一任务；返回回到来时页面 |
| 预期接口 | `GET /jobs?active=true` 驱动任务条；进详情 `GET /jobs/{id}` |
| 断言点 | 任务条只在非终态出现；终态后任务条消失；进入详情不创建任务 |
| 失败分支 | 任务条数据过期（任务已结束）：点进去详情显示终态，任务条刷新后消失 |

### A05 浏览器刷新

| 项 | 内容 |
| --- | --- |
| 入口 | 任务详情、报告阅读器、任务列表筛选态 |
| 操作 | F5 刷新；再直接粘贴深链接打开 |
| 预期界面 | 详情重建后阶段与按钮一致；报告回到原章节；列表筛选和滚动位置恢复 |
| 预期接口 | `GET /jobs/{id}` + SSE 带本地 `Last-Event-ID`；报告 `GET /reports/{id}` + `#sec-xxx` |
| 断言点 | 刷新不创建 job；筛选从 query 恢复；章节不存在时停在顶部不报错 |
| 失败分支 | 游标过期 410 `sse_cursor_expired`：整页重建，不重放旧事件 |

### A06 SSE 断线

| 项 | 内容 |
| --- | --- |
| 入口 | 运行中的 `/jobs/:jobId` |
| 操作 | 断开网络 10 秒再恢复；再模拟服务端关闭事件流 |
| 预期界面 | 顶部黄条「正在重连，阶段可能延迟」；恢复后自动消失；终态后不再重连 |
| 预期接口 | 重连带 `Last-Event-ID`；服务端补发缺失事件；心跳 `: ping` |
| 断言点 | seq 连续；重连没有调用 `POST /jobs`；终态收到 `status_changed` 与 `report_ready` 后连接关闭 |
| 失败分支 | 重连间隔逐步拉长；410 时改为刷新恢复 |

### A07 暂停和恢复

| 项 | 内容 |
| --- | --- |
| 入口 | 运行中的任务详情 |
| 操作 | 点「暂停」→ 等阶段边界 → 点「继续」 |
| 预期界面 | 暂停后按钮只留「取消」；显示「已受理，将在当前阶段结束后生效」；状态变「已暂停」；继续后从下一阶段接着跑 |
| 预期接口 | `POST /actions {pause}` 202 → `status_changed` → `POST /actions {resume}` 202 |
| 断言点 | 暂停和恢复都是同一个 job id；没有新建任务；恢复后阶段序号继续递增 |
| 失败分支 | 暂停期间取消：先到 `cancel_requested` 再 `cancelled`；重复暂停返回 200 `already_pending` |

### A08 取消确认

| 项 | 内容 |
| --- | --- |
| 入口 | 运行中或暂停中的任务详情 |
| 操作 | 点「取消」→ 在确认框确认；再试一次不确认 |
| 预期界面 | 确认框写明「已产生的模型费用不退，且不会生成完整报告」；确认后按钮全部消失，显示「取消中」；不确认则什么都不发生 |
| 预期接口 | 确认后 `POST /actions {cancel}` 202；`cancel_requested` 的 `allowed_actions` 为空 |
| 断言点 | 取消只在阶段边界生效；终态 `cancelled` 无 report_id；重复取消 200 `already_pending` |
| 失败分支 | 任务刚好完成：取消返回 409 `illegal_transition`，界面刷新为已完成并给报告入口 |

### A09 失败后重新分析

| 项 | 内容 |
| --- | --- |
| 入口 | `failed` 任务详情 |
| 操作 | 先点「重试」；再回到启动器改配置点「重新分析」 |
| 预期界面 | 重试给新任务并跳新详情；旧任务保持失败；重新分析走全新幂等键 |
| 预期接口 | `POST /jobs/{id}/retry {mode: same_config}` 201；`retry_of_job_id` 指向旧任务 |
| 断言点 | 旧任务字段不变；新任务配置与旧任务一致；重复点重试不产生两个新任务 |
| 失败分支 | 失败原因是数据源不可用：重试前提示「数据源刚恢复，可重试」，不自动重试 |

### A10 中断后人工处理

| 项 | 内容 |
| --- | --- |
| 入口 | `interrupted` 任务详情 |
| 操作 | 先看「从检查点继续」；再在有 fingerprint 变化时尝试继续 |
| 预期界面 | 说明从中断阶段继续、会补跑哪些阶段；fingerprint 不一致时只给「重新分析」 |
| 预期接口 | `POST /jobs/{id}/retry {mode: resume_from_checkpoint}` 201；新 job 带 `resume_of_job_id` 与 `resume_from_stage` |
| 断言点 | 原任务保持 `interrupted`；新任务从首个未完成阶段开始；不会自动续跑 |
| 失败分支 | 409 `resume_fingerprint_mismatch`：界面不显示重试按钮，只留重新分析 |

### A11 完成后打开报告

| 项 | 内容 |
| --- | --- |
| 入口 | `succeeded` 任务详情 |
| 操作 | 等 `report_ready` 后点「打开报告」 |
| 预期界面 | 按钮在 report_id 为空时不出现，显示「报告生成中」；ready 后直接进阅读器 |
| 预期接口 | `GET /jobs/{id}` 的 `report_id`；`GET /reports/{id}` |
| 断言点 | 打开报告不触发 PDF、不拉行情；报告内容与任务评级一致 |
| 失败分支 | 报告提交失败：状态仍是 succeeded 但 report_id 为 null，详情显示「报告不可用，请联系维护」并给重试读取 |

### A12 报告章节跳转

| 项 | 内容 |
| --- | --- |
| 入口 | 报告阅读器目录 |
| 操作 | 点「多空辩论」；复制带 `#sec-debate` 的 URL 新开；再点一个不存在的 `#sec-missing` |
| 预期界面 | 滚动到章节且目录高亮；移动端抽屉自动关闭；不存在时停在顶部 |
| 预期接口 | 无额外请求（正文已加载）；URL 只变 hash |
| 断言点 | 刷新后仍停在 `#sec-debate`；13 个章节 id 与 ReportDTO 一致 |
| 失败分支 | 历史报告缺该章节：目录项置灰，不跳转 |

### A13 PDF 显式生成

| 项 | 内容 |
| --- | --- |
| 入口 | 报告阅读器「导出 PDF」 |
| 操作 | 点一次并等待；渲染中再点一次；完成后下载 |
| 预期界面 | 未点击前不生成；点击后显示进度；重复点击不重复渲染；完成后给下载 |
| 预期接口 | `POST /reports/{id}/exports/pdf` → 202/200；`GET /exports/{id}` 轮询；`GET /exports/{id}/file` |
| 断言点 | 打开报告不生成 PDF；缓存键命中时 200 + `X-Export-Cached: 1`；未 ready 取文件 409 `export_not_ready` |
| 失败分支 | 渲染失败：状态 `failed` + 安全错误文案 + 重试；重试复用同一导出任务还是新建由实现定，界面不暴露内部 id |

### A14 返回列表恢复上下文

| 项 | 内容 |
| --- | --- |
| 入口 | `/jobs` 或 `/reports` 的筛选态 |
| 操作 | 设状态多选、股票、日期、评级 → 进详情或阅读器 → 浏览器返回 |
| 预期界面 | 筛选、游标位置、滚动位置原样恢复 |
| 预期接口 | 无新增请求或用 query 重放 `GET /jobs` / `GET /reports` |
| 断言点 | 返回不清空筛选；直接打开详情后返回列表，用 query 重建；不出现「筛选丢失」 |
| 失败分支 | 无历史记录（新标签页直接打开详情）：返回按钮回默认列表页，不带筛选 |

## 2. 移动专项八条

| 编号 | 检查项 | 判定方法 | 线框证据 |
| --- | --- | --- | --- |
| M01 | 首屏能看到主操作 | 390×844 首屏内出现「开始分析」/「分析这只股票」主按钮，无需滚动 | W01、W07 移动线框 |
| M02 | 底部导航不遮挡按钮 | 吸底操作条位于导航之上；同时出现时按钮完整可见 | W02、W04、W06、W07 |
| M03 | 触控区域至少 44px | 量测主按钮、次按钮、导航项高度，全部 ≥44px | `shoot_wireframes.py` 自动量测，390/360 均无低于 44px 的项 |
| M04 | 报告目录使用抽屉 | 目录不占正文列，点「目录」从底部弹出，选中后关闭 | W06 移动线框 |
| M05 | 任务阶段不挤成多列 | 12 个阶段单列时间线，当前阶段高亮，不出现两列以上 | W04 移动线框 |
| M06 | 表格转换为摘要卡片 | 任务、报告、行业、强势股在移动端均为卡片，不渲染表格 | W03、W05、W08 移动线框 |
| M07 | 360px 无页面级横向滚动 | `documentElement.scrollWidth == clientWidth`；仅图表、指数条、页签、目录允许容器内滚动 | 360 视口自动检查通过（360/360） |
| M08 | 日志没有不可控双层滚动 | 日志页在服务不可用时是说明页，不嵌 iframe；可用时 iframe 高度由容器固定，页面本身不滚动 | W09 移动线框 |

移动端另外两条实现约束（P1 检查）：

- 吸底条要留安全区 `env(safe-area-inset-bottom)`，否则全面屏底部会压住按钮。
- 抽屉打开时锁页面滚动，关闭后恢复原位置；不允许页面与抽屉同时滚动。
