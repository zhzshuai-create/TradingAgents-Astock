## 四、契约行为

依据：`core-wireframes.md` 第 3 节 W03、`interaction-checklist.md` A14/M06、`api-v1.md` 1.4。

### 4.1 筛选与 URL

- 筛选：九状态多选（默认全选）、股票代码、分析日期范围、只看活动任务开关、重置。
- 默认请求：不写 `status`（等价全部）、不写 ticker/日期/active，`GET /api/v1/jobs?limit=20`。
- `status` 用逗号连接一次请求；全选时省略该参数，不写 `status=`。
- 只看活动任务开启时只发 `active=true`，必须同时省略 `status`；两者同时出现后端会 400 `invalid_request`。
- `active` 与 `status` 在界面上互斥：打开活动开关时状态多选禁用或隐藏，关闭后恢复原选择。
- 股票代码只接受 6 位数字；日期范围按分析日期，`date_from <= date_to`。
- 非法状态、非法日期、非 6 位代码在写进请求前丢弃并回落到默认，不把 400 打给用户。
- 筛选与游标全部写进 query；直接打开深链接按 query 重建 UI 并发对应请求。
- 任一筛选变化都重置 `cursor` 与已加载列表；刷新页面后筛选不丢。
- 返回列表时的滚动位置与「已加载页」恢复放到 P2-13 的 A14；本票只保证 query 在 URL 里、浏览器后退不丢筛选。

### 4.2 桌面表格

- 列：股票（名称+代码）、分析日期、状态、当前阶段、耗时、创建时间、查看。
- 状态徽标复用 `JOB_STATUS_META`；`interrupted` 显示「等待人工处理」，不得写成「运行中 / 进行中」。
- 活动任务（`queued` / `running` / `pause_requested` / `paused` / `cancel_requested`）的当前阶段带进度条；`current_stage` 为 null 时显示「阶段切换中」，不伪造阶段号。
- 失败行在状态列显示 `error` 的安全文案；只取 `ApiError`/投影里的 message，不渲染响应体、堆栈或路径。
- 「查看」只导航到 `/jobs/:jobId`，不发写请求。

### 4.3 移动卡片

- 767px 以下不渲染表格；每行是摘要卡片：第一行股票名+状态徽标，第二行日期+阶段，第三行耗时。
- 整卡可点；不做行内按钮。
- 「筛选」打开全屏筛选页（复用 `Dialog` 的 `fullscreenOnMobile` 或现有 `Drawer`）；应用后在标题下显示已选条件 chips。
- 390 与 360 无页面级横向滚动；触控项不小于 44px。

### 4.4 翻页与状态

- 首屏与每次追加固定 `limit=20`；「加载更多」用上一页 `next_cursor`，不手拼 offset。
- 「加载更多」失败保留已加载项，只给重试；重试沿用同一个游标。
- 空列表：说明还没有任务，给「开始一次分析」进 `/workbench?launch=1`。
- 筛选后为空：说明没有符合条件的任务，给「清空筛选」。
- 首屏请求失败：给重试并保留当前筛选，不清空 URL。
- 不自动轮询整页；活动行的阶段进度本票用列表快照，P2-11 起再补实时。若要做局部刷新，只允许对单任务详情查询，不得整页重取。

## 八、必须守的约束

- 只有 `GET /api/v1/jobs`；本票不产生任何写请求。
- `status` 与 `active` 互斥；全选状态省略参数，不写空值。
- 只按服务端返回的九状态渲染，不新增状态名或前端自造状态。
- 游标不透明，只回传服务端 `next_cursor`；不得解析、拼接或持久化。
- 组件不直接 `fetch`，不写 `/api/v1` 字面量；地址只在 `frontend/src/api/`。
- 错误文案只从 `ApiError.message` 或契约文案取，不渲染响应体、堆栈或路径。
- 状态与阶段文案集中在 `jobStatus.ts`，列表、任务条、工作台共用一份。
- 移动端不渲染表格；表格只给 768px 以上。
- `data-testid="page-jobs"` 保持不变，E2E-01/02 的深链断言依赖它。
- 一票一本地提交，不推送；存档单独提交。

## 九、容易踩的坑

1. 当前占位页写的是「将在 P4 接入」，替换时连文案一起删，别让旧承诺留在页面上。
2. `listPath()` 在 `active === true` 时会忽略 `status`；界面必须与请求同口径，不要把两者同时勾选。
3. 后端对未知 `status` 与 `date_from > date_to` 会 400；前端先在 `listParams` 里清洗，别把 URL 上的脏值直接发出去。
4. 全选九状态等于不过滤，但不要发 `status=` 空串；契约只接受逗号连接的非空值。
5. 游标是 `created_at + \x1f + job_id` 的 base64url，换筛选必须清空；把游标也写进 URL 时按不透明字符串处理。
6. `current_stage` 在阶段切换间隙可能为 null；显示「阶段切换中」，进度条不跳到 0/12。
7. `interrupted` 的标签是「等待人工处理」，列表与徽标都不得写「运行中 / 进行中」。
8. 移动端用 CSS 断点隐藏表格，不要用 `window.innerWidth` 条件渲染；jsdom 不执行媒体查询，M06 由 E2E 覆盖。
9. 移动筛选页不要出现页面级双层滚动；筛选列表自身滚动，页脚按钮固定。
10. 空数组状态不要把 `[]` 当作「全不选」：契约里空筛选等于全选，UI 可用「没勾任何状态」表示全选或直接禁止取消最后一个。
11. 深链接里的非法值要静默丢弃并重建默认 UI，不要抛错页；首屏请求失败才给重试。
12. 返回列表的滚动恢复是 P2-13 的 A14，不要在本票自造 sessionStorage 方案；只保证筛选在 URL、后退可用。
13. 活动任务条与列表页可能同时读 `["jobs", filters]` 与 `["jobs"]` 前缀；失效仍用现有 `invalidateJobQueries`，不要另造键。
14. `limit` 契约未定义小于 1；本票固定 20，不开放给用户。
15. E2E 桩必须处理带 query 的 URL；用 `**/api/v1/jobs**`，并按 `url.parse_qs` 校验参数，别只按精确 URL 匹配。
