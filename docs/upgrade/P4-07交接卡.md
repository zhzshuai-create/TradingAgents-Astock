## 三、P4-07 交付了什么

- 视口分支：`useIsMobile` 读 `matchMedia('(max-width: 767px)')`，挂载读一次并监听变化；整页切到移动分支，不是 CSS 双渲染。
- 指数条：`IndexStrip` 横向 flex + scroll-snap，单卡 `min(82%, 320px)`；横滑只发生在条内，`document` 与 `#main-content` 的 `scrollWidth === clientWidth`。
- 行业卡：排名、行业、涨跌幅、上涨/下跌家数、领涨股；整卡可点，选中态用 `data-active` 与 `aria-pressed`；末位 5 家单独标「涨幅末位」。
- 强势卡：名称、代码、涨跌幅、题材、最新价、换手；题材芯片与桌面一致（全部 + TOP8），筛选只作用于当前列表。
- 全屏成分股：`BoardStocksDialog` 用 portal 铺满视口，标题「行业名 · 成分股」，10 行链接到 `/stocks/:code?tab=valuation`；关闭清 `board`，返回按 URL 重开。
- 交互细节：全屏层复用 `useDialogFocus`（焦点陷阱、Esc、焦点归还），滚动锁覆盖 `body` 与 `[data-scroll-lock]`；关闭或从个股返回都保持原滚动。
- 移动端 DOM 中没有 `<table>`，桌面表和抽屉组件根本未挂载。
- 触控：行业卡 64 px、强势链接 44 px、芯片/select/日期/「最新」44 px、成分股行 56 px、关闭按钮 44×44。
- 代码复用：抽出 `IndexCard` 与 `themeFilter`，桌面与移动共用同一批查询与筛选逻辑，桌面行为不变。

## 八、容易踩的坑

1. jsdom 没有真实媒体查询：`MarketPage.mobile.test.tsx` 在 `beforeEach` 桩 `matchMedia`、`afterEach` 还原；`useIsMobile` 挂载时才读，桩必须在那之前生效。
2. 一个页面有 25 个 `industry-card`：`findByTestId` 会因多个匹配报错，用 `findAllByTestId(...)[0]` 或按 `data-code` 定位。
3. 390×844 高度下行业卡本来就在首屏，`scroll_into_view_if_needed` 不会产生位移；要验证滚动恢复必须先显式 `scrollTop = 500`。
4. 返回恢复依赖「第二次点击」写入带 `board` 的 sessionStorage 键；只断言弹层开合不够，必须点成分股行再返回。
5. 桌面日期控件改 URL 是同步的、发请求是异步的；E2E 断言请求必须轮询，不能紧跟 `wait_for_url`。
6. 全屏层不要改共享 `Dialog`：桌面仍用右侧 `Drawer`，两者交互形态不同；新组件复用 `useDialogFocus` 即可。
7. 移动端不要保留「表格包在横滑容器」的兼容层；W08M-02 要求 DOM 中无 `<table>`，CSS 隐藏不算。
8. 全页截图里固定底栏会画在长图末尾，不代表首屏遮挡；检查遮挡要看普通视口截图或 `bounding_box`。
9. 全量 vitest 并行负载下 AppShell 首条 `/workbench` 用例偶发 1 s 查找超时（单文件与复跑均过）；遇到先复跑再判断。
10. `check_bundle.mjs` 默认写 P4-04 拆包证据，本票用 `--out` 临时文件；`e2e_p3.py` 仍会改写 P3-09 性能证据，复跑后 `git checkout --` 还原。
