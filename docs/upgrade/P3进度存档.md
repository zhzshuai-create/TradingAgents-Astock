### 1.4 已经定死、不要再改的口径

1. 章节顺序只有一份来源：`report_render.ordered_sections()`；前端 `sections.ts` 是镜像，不另造顺序。
2. 章节存在判定：正文非空，或任一 part 非空，或 `parts_ref` 非空；不存在或为空的章节不渲染、不进目录（不是灰显）。
3. 缺失章节的章号保留契约序号，不重新编号（`sec-market` 永远是 2）。
4. 深链只操作 DOM 与 URL：点击、刷新、缺失锚点都不发额外请求；缺失锚点停顶部、不报错。
5. 点击目录用 `navigate(..., { replace: true, preventScrollReset: true })`，避免污染返回栈和重复滚动。
6. 决策卡缺失值统一「—」；`ReportSignal` 的 `unknown` 视为缺失，不显示英文原词。
7. 元信息只读 DTO：生成时间不读 mtime，任务链接只看 `job_id` 是否为 null。
8. Markdown 安全面：`skipHtml` + 默认 URL transform；只给 http(s) 外链加 `target` / `rel`；非 http(s) 图片不生成 `<img>`。
9. 高亮算法：root 为 `#main-content`，`rootMargin: "0px 0px -92% 0px"` 顶部细带；重叠时取靠后章节；滚到底强制末章；`maxScroll <= 4` 时不触发（jsdom 保护）。
10. 详情缓存：`staleTime: 60_000`、`retry: false`；一次打开只发一次详情 GET，60 秒内重进复用缓存。
11. 报告 GET 零副作用；导出 `POST` 必须由用户点击触发（P3-07），P3-06 不得提前发请求。

### 1.5 已经踩过的坑

1. `#main-content` 是滚动容器，外壳在导航开始时把 `scrollTop` 归零且旧页面仍挂载；滚动位置不能在卸载或滚动事件里保存（P3-04 的现场恢复为此改成点击捕获 + popstate）。
2. Playwright 点击前会把目标滚进视口，测试滚动位置时必须点击「当前已在视口内」的行。
3. 只改 hash 的 `page.goto` 是同文档导航，不会重新挂载 React；要测深链加载先 `goto("about:blank")` 或 `reload()`。
4. jsdom 没有 `IntersectionObserver`，`scrollIntoView` 也不存在；组件测试用假 observer，并在 `beforeAll` 里定义 `Element.prototype.scrollIntoView`。
5. `react-markdown` v10 默认不解析 GFM 表格，必须挂 `remark-gfm`（bundle 增加约 17 kB）；`skipHtml` 与默认 URL transform 仍生效。
6. 相邻章节首尾相接，任意「顶部带」都会同时命中上一章；高亮必须取靠后章节，并在到底部时强制末章。
7. 404 是预期分支时，Chromium 会打一条 `Failed to load resource` 控制台错误；E2E 只过滤这一条，其余错误仍算失败。
8. Vite 的 gzip 数字按 1000 字节为 kB；证据 JSON 记录原值，不四舍五入。
9. Windows 控制台是 GBK，直接打印中文 fixture 会乱码；E2E 脚本开头统一 `stdout.reconfigure(encoding="utf-8")`。
