### 1.4 已经定死、不要再改的口径

1. 章节顺序只有一份来源：`report_render.ordered_sections()`；前端 `sections.ts` 是镜像，不另造顺序。
2. 章节存在判定：正文非空，或任一 part 非空，或 `parts_ref` 非空；不存在或为空的章节不渲染、不进目录（不是灰显）。
3. 缺失章节的章号保留契约序号，不重新编号（`sec-market` 永远是 2）。
4. 深链只操作 DOM 与 URL：点击、刷新、缺失锚点都不发额外请求；缺失锚点停顶部、不报错。
5. 点击目录用 `navigate(..., { replace: true, preventScrollReset: true })`，避免污染返回栈和重复滚动。
6. 决策卡缺失值统一「—」；`ReportSignal` 的 `unknown` 视为缺失，不显示英文原词。
7. 元信息只读 DTO：生成时间不读 mtime，任务链接只看 `job_id` 是否为 null。
8. Markdown 安全面：`skipHtml` + 默认 URL transform；只给 http(s) 外链加 `target` / `rel`；非 http(s) 图片不生成 `<img>`。
9. 高亮算法：root 为 `#main-content`，`rootMargin: "0px 0px -92% 0px"` 顶部细带；重叠时取靠后章节；滚到底强制末章；`maxScroll <= 4` 时不触发（jsdom 保护）。
10. 详情缓存：`staleTime: 60_000`、`retry: false`；一次打开只发一次详情 GET，60 秒内重进复用缓存。
11. 报告 GET 零副作用；导出 `POST` 只能由用户点击「导出 PDF」触发：打开阅读器、轮询、重试按钮出现都不发 POST。
12. 移动分支只按 `(max-width: 767px)` 的 `matchMedia` 判定，与外壳断点一致；目录列与表格用渲染分支移除，不用 CSS 隐藏。
13. 抽屉里的跳章必须先关抽屉、下一拍再滚动；抽屉的 `overflow:hidden` 锁会吞掉同拍的 `scrollIntoView`。
14. 吸底条 `bottom = 56px + env(safe-area-inset-bottom)`，与 `MobileNav` 高度对齐；吸底条与桌面头部共用 `useReportActions` 的同一套状态，不各写一份。

### 1.5 已经踩过的坑

1. `#main-content` 是滚动容器，外壳在导航开始时把 `scrollTop` 归零且旧页面仍挂载；滚动位置不能在卸载或滚动事件里保存（P3-04 的现场恢复为此改成点击捕获 + popstate）。
2. Playwright 点击前会把目标滚进视口，测试滚动位置时必须点击「当前已在视口内」的行。
3. 只改 hash 的 `page.goto` 是同文档导航，不会重新挂载 React；要测深链加载先 `goto("about:blank")` 或 `reload()`。
4. jsdom 没有 `IntersectionObserver`，`scrollIntoView` 也不存在；组件测试用假 observer，并在 `beforeAll` 里定义 `Element.prototype.scrollIntoView`。
5. `react-markdown` v10 默认不解析 GFM 表格，必须挂 `remark-gfm`（bundle 增加约 17 kB）；`skipHtml` 与默认 URL transform 仍生效。
6. 相邻章节首尾相接，任意「顶部带」都会同时命中上一章；高亮必须取靠后章节，并在到底部时强制末章。
7. 404 是预期分支时，Chromium 会打一条 `Failed to load resource` 控制台错误；E2E 只过滤这一条，其余错误仍算失败。
8. Vite 的 gzip 数字按 1000 字节为 kB；证据 JSON 记录原值，不四舍五入。
9. Windows 控制台是 GBK，直接打印中文 fixture 会乱码；E2E 脚本开头统一 `stdout.reconfigure(encoding="utf-8")`。
10. `Drawer` 打开时给 `#main-content` 加 `overflow:hidden`；跳章若与关闭同拍，`scrollIntoView` 不生效（E2E 实测 gap 撞到 5 万像素）。改成记录待跳章节、用 `useEffect` 在 `tocOpen` 变 false 后执行。
11. jsdom 没有可用的 `matchMedia`；组件测试用 `stubViewport()` 覆盖 `window.matchMedia`，并在 `afterEach` 按原属性描述符还原，避免污染桌面用例。
12. 导出轮询 600 ms 会让 MSW 用例真正等待一拍；断言「未点击零请求」不能只看渲染后瞬间，要 `waitFor` 超过一个轮询周期再确认计数仍为 0。
13. 导出状态 GET 的失败不是 `ApiError`（没有 envelope），`displayErrorMessage` 只接受 `ApiError` 与 `unknown`；文案兜底不要假设后端给了 `error.message`。
14. 启动器与工作台主按钮同名「开始分析」；Playwright 严格模式会命中两个，必须 `dialog.get_by_role("button", name="开始分析")` 收窄到弹窗内。
15. 下载 URL 在前端拼 `/api/v1/...` 会绕过 base URL 配置；测试断言的是 `resolveUrl` 结果（绝对地址），相对路径写法会挂。
16. Streamlit `AppTest` 渲染报告正文会连带生成 PDF 图表并懒拉 K 线；不测试数据层时必须同时打桩 `index_spot`、`tencent_quote`、bars 预热、`_get_kline_full`、mootdx 客户端、`pdf_export.generate_pdf` 与 `journal_service.start_journal`，否则用例会去连 TDX 服务器。
17. 投影默认开启会影响所有测试的 HOME；`tests/conftest.py` 用 autouse fixture 设 `TA_LEGACY_PROJECTION=0`，需要投影的用例再显式置 `1`，保证没有测试写真实 `~/.tradingagents`。
18. 旧版阅读器只渲染 `investment_plan` 与辩论/风控的 bull/bear/judge、aggressive/conservative/neutral，`history` 字段不显示；无法还原的部分必须并进 judge，否则用户看不到。
19. Playwright 的 `**/api/v1/reports**` 同时匹配 `/api/v1/reports/<id>`；只在后面注册单段 glob `**/api/v1/reports/*` 才能让详情拿到 ReportDTO。否则阅读器收到列表 JSON，`meta` 为空，`page-report-detail` 只剩空骨架；等 section 可见的用例会在骨架期偶发通过，P3-04 起一直潜伏，P3-09 首次复现。
