### 5.2 备份实现

- 数据库：`sqlite3.connect(src).backup(dst)` 导出到同盘临时文件。`jobs.db` 是 WAL 模式，直接复制文件会拿到撕裂快照或漏掉 `-wal`。
- 收文件：按白名单递归；路径一律用相对数据根的 POSIX 风格写进 zip，禁止绝对路径与 `..`。
- 排除优先于包含：即使白名单目录里出现 `cache/`，也不入包。
- zip 固定放在 `--out` 指定的路径；默认建议 `~/tradingagents-backups/backup-YYYYMMDD-HHMMSS.zip`，创建目录前先打印将要写入的绝对路径。
- 同一份快照先算 sha256 再写 zip，zip 写完后重读校验一次。

### 5.3 manifest 字段

`manifest.json` 至少包含：

```text
created_at            带 +08:00 的时间
source_root           数据根绝对路径（只在本地清单里，不上报）
write_mode            ACTIVE_ANALYSIS_UI 的实际取值，缺省写 legacy
migration_head        只读取得的迁移头
included              实际入包的白名单项
excluded              固定排除项（常量，不随目录内容变化）
db                    { path, bytes, sha256 }
files                 [{ path, bytes, sha256 }]
counts                { files, bytes }
```

不允许写入 `llm_config.json` 的内容、任何 API Key、任何数据库行内容。

### 5.4 还原流程

1. 读 zip 里的 `manifest.json`，逐项重算 sha256；不一致直接拒绝，不解包。
2. dry-run（默认）：打印将新增、将覆盖、将保留的文件清单与字节数，退出码 0。
3. `--apply`：
   - 确认目标后端已停：对 `jobs.db` 尝试独占打开（Windows 下用 `os.open` + 替换探测）；被占用就报“后端仍在运行，先停止 8600/8501”，不改任何文件。
   - 解包到同盘临时目录（同盘才能原子替换）。
   - 把目标文件移动到 `pre-restore-<timestamp>/` 保留，再按文件替换；不用整目录删除。
   - 替换后重算关键文件 sha256，与 manifest 对比，打印结果。
4. 数据库恢复前如果存在 `jobs.db-wal` / `jobs.db-shm`，一并移入 `pre-restore-*`，不要再放回去。

### 5.5 后端是否在运行的判定

不要靠“端口开着”单独判断（用户可能只开了旧版）。以目标文件能否被替换为准：还原前对每个将被覆盖的文件做一次独占打开/改名探测，失败即停止。这一条写进手册的断言里。

### 5.6 回滚手册八步

按计划 8.8：禁止新版创建 → 等终态或协作取消 → 切回旧版 → 验证兼容投影可读（`legacy_projection`，默认开启）→ 保留新版只读入口 → 迁移不降级 → 数据损坏时恢复备份 → 不触碰交易日志。每步给：命令、可观测断言、预计耗时、失败时停在哪。数据步骤只在备份副本上做，真实目录替换单独一步并标注“需人工确认”。
