## 五、口径

### 5.1 九个核心页与 landmark（SR-02）

- 页面清单：`/workbench`、`/market`、`/stocks/:ticker`、`/jobs`、`/jobs/:id`、`/reports`、`/reports/:id`、`/journal`、`/settings`。
- 每页恰好一个 `h1`；`h2` 只作为 `h1` 的下级，不出现 `h1 → h3` 的跳级。分组标题、卡片标题一律 `h2`。
- 外壳已有 `aside[aria-label=主导航]`、`nav[aria-label=页面导航]`、`main#main-content`；页面内只在确有导航语义时加 `nav`，不要给普通列表套 `nav`。
- 不新增第二个 `main`，不给装饰容器加 `role="region"` 除非有 `aria-label`。

### 5.2 表格语义（SR-06）

- 任务表、报告表、市场行业表、股票报告表：`<table>` 必须有 `caption`（可用视觉隐藏样式），列头用 `<th scope="col">`，行首标识用 `<th scope="row">`。
- 纯展示的键值对继续用 `dl`，不要为了「像表格」改成 `table`。
- 报告正文里的 Markdown 表格由 `ReportMarkdown.tsx:121` 渲染；若无法稳定加 `caption`，至少保证表头是 `th`，并把该处记入结果 JSON 的已知限制。

### 5.3 图表文本替代（SR-05）

- 两个 SVG 至少要有 `role="img"` 与一个随数据变化的 `aria-label`（例如「贵州茅台 日内分时，09:30 至 15:00，最新 1680.00 元」）。
- 同一页提供一句可见或视觉隐藏的文本摘要，让读屏用户不依赖图形；摘要不能编造快照里没有的数字。
- 空数据与 stale 状态不画图时，名称与摘要要说明原因，不要留下空 `img`。

### 5.4 实时区（SR-04）

- 状态变化用 `role="status"` + `aria-live="polite"`；阻塞性错误用 `role="alert"`；两者不要嵌套。
- 已有实时区保持不动（任务详情、日志、设置已保存、Toast、StaleBanner）；只补缺失的刷新完成与日志状态切换。
- 同一时刻只允许一个主要实时区播报，避免重复朗读；装饰性数字变化不加 `aria-live`。

### 5.5 减少动态（RM-01 至 RM-03）

- `global.css:56-63` 已把时长压到 `0.01ms`；本票要确认没有绕过它的写法：内联 `style` 动画、`requestAnimationFrame` 数字滚动、`scroll-behavior: smooth`、`element.scrollTo({ behavior: "smooth" })`。
- 逐项核对 `fade-in`、`pop-in`、`slide-in-*`、`toast-in`、`shimmer`：开启减少动态后不得有持续动画；`Skeleton` 已单独置 `animation: none`，不要重复覆盖。
- 开启减少动态时，焦点移动与面板开合仍然可用，只是没有过渡；不得用 `display: none` 代替动画。

### 5.6 对比度（手工抽检，正式门禁在 P5-08）

- 抽检范围：亮/暗两套的正文、次要说明、状态徽标、按钮文字、禁用态、焦点环。
- 阈值：正文与控件文字 ≥4.5:1，大字（≥18.66px 粗体或 ≥24px）≥3:1；焦点环与相邻背景 ≥3:1。
- 只记录实测结果与不达标项；需要改色时只动令牌，不在组件里写死颜色。
