# P6 任务拆票：双栈灰度、性能与回滚

版本：v1（2026-11-07）
上游：`docs/upgrade/reviews/2026-11-07_P5出口评审.md` 结论为 Go；`p5-backlog.md` 第 7 节；计划书 8.5–8.8、9 节 P6 行与十四节发布清单。
用途：把 P6 拆成 8 张可独立验收的票（P6-00 至 P6-07）。每票单独提交、单独回退、单独跑测试。

P6 收口双栈灰度：唯一分析写入者开关、备份与恢复、真实 Canary、LCP/CLS/INP 门禁、默认入口切换与回滚演练。**P6 结束前默认入口仍是旧版 Streamlit**；新 React 只是并行可写者。交易日志保持独立服务与独立数据。

## 0. 公共约束

- 技术栈不换：React 19 + TypeScript + Vite + TanStack Query；后端 FastAPI + SQLAlchemy + Alembic。
- 唯一写入者：任何时刻只允许一个入口创建分析。`ACTIVE_ANALYSIS_UI=legacy | next`，默认 `legacy`。
- 契约：按 `FREEZE-v1.md` 第 1 节，P6 允许「新增可选字段」与「新增错误码（不复用既有码含义）」，不升版本；但必须在同一次提交更新 `FREEZE-v1.md` 的哈希与当日评审理由，并同步测试。
- 迁移只做新增式，不要求降级；备份覆盖 SQLite 与 `~/.tradingagents`。
- 不碰 `trade-journal` 仓库与其数据；不合并交易日志数据库。
- 后端不得 `import web.*`；测试不联网、不读 API Key、不读写真实 `~/.tradingagents`（Canary 与回滚演练除外，且必须显式 `--live`/`--restore` 才动真实目录）。
- 一票一本地提交，不推送；代码与证据分开提交。开工前与收工前预检必须 10 项 PASS。

## 1. 票内定稿

### 1.1 七项决定

**D1 开关只读一次，默认 legacy**

`ACTIVE_ANALYSIS_UI` 在进程启动时读取一次并缓存；非法值启动即失败，不静默回退。默认 `legacy`。切换写入者必须重启后端，不做运行期热切换，避免两个入口同时拿到写权。

**D2 写入者状态由后端回答，前端不猜**

`GET /api/v1/meta/options` 新增可选键 `write_mode: "legacy" | "next"`（新增可选字段，不升版本）。`tests/backend/test_meta_options.py` 的 META-01 从「恰好八个键」改为「八个既有键 + 可选 `write_mode`」，逐键断言保留。

**D3 legacy 模式下的拒绝方式**

`next` 模式下旧版分析入口禁用；`legacy` 模式下新版 `POST /api/v1/jobs` 返回 `409 write_mode_legacy`。新错误码写进 `error-codes-v1.md`，用户动作写「请在旧版发起分析」。不复用 `active_conflict`、`idempotency_mismatch` 或 `illegal_transition`。

**D4 备份是目录快照，不是数据库导出**

`scripts/backup_restore.py`：`backup` 把 SQLite 文件与 `~/.tradingagents` 打进带时间戳的 zip，附带 `manifest.json`（文件数、大小、sha256、迁移头、`ACTIVE_ANALYSIS_UI`）；`restore` 校验 sha256 后先解到临时目录，再原子替换，替换前把当前状态另存为 `pre-restore-*`。默认 dry-run，必须 `--apply` 才写盘。

**D5 Canary 一次、限额、可举证**

Canary 是一次人工批准的真实模型分析，费用上限由人工在 ticket 内写明。允许入口：`ACTIVE_ANALYSIS_UI=next` 且单任务。取证：任务详情的事件流、`model_calls` 与报告 `content_hash`；断言「同一 `Idempotency-Key` 重放不产生第二次模型调用」。

**D6 性能门禁用构建产物，不用开发服务器**

LCP ≤2.5s、CLS ≤0.1、缓存交互 INP ≤200ms，在 `vite preview` + 桩接口下用 Playwright PerformanceObserver 采样，手机档 390×844 与桌面 1440×900 各 20 样本取 p75。数据来自夹具，不联网，样本量与时延线写进证据 JSON。

**D7 切换与回滚都是脚本，不是手工步骤**

`scripts/stack_mode.py set legacy|next` 写 `ACTIVE_ANALYSIS_UI` 到 `.env.stack`，`run_all.bat` 与新版启动脚本都读它。回滚演练按计划 8.8 的八步执行，每步有可观测断言；演练前后各做一次备份并校验 sha256。

### 1.2 冲突预案

| 编号 | 冲突 | 定稿口径 |
| --- | --- | --- |
| C1 | `meta/options` 现有 META-01 断言恰好八键 | 新增可选键后同步改断言为「八键必在 + `write_mode` 可选」，仍逐键 |
| C2 | 计划 8.5 只说「返回冲突」，没给错误码 | 新增 `write_mode_legacy`（409），不复用既有码 |
| C3 | 旧版没有「分析入口禁用」机制 | `legacy` 模式零改动旧版；`next` 模式下旧版禁用靠 `ACTIVE_ANALYSIS_UI` 与启动脚本，不改 `web/` 代码 |
| C4 | 备份包含 `~/.tradingagents`，可能含密钥文件 | 备份只收报告、状态与配置的非敏感部分；`manifest.json` 记录排除项，密钥永不入包 |

| C6 | 回滚演练会动真实数据 | 演练在备份副本上做，真实目录只在最后一步由人工确认 |

## 3. 每票要点

### P6-01 唯一写入者开关

- `backend/app/core/write_mode.py`：读 `ACTIVE_ANALYSIS_UI`，非法值启动失败。
- `POST /api/v1/jobs` 在 `legacy` 模式返回 `409 write_mode_legacy`；幂等判定顺序不变（先幂等后写入者）。
- `error-codes-v1.md` 新增错误码，同步 `FREEZE-v1.md` 哈希。
- 前端启动器在 `legacy` 模式显示「当前由旧版发起分析」并禁用提交；提交按钮不得假装成功。

回退：删除开关与错误码，恢复 `meta/options` 八键与 `POST /jobs` 原行为。

### P6-02 写入者状态展示

- `meta/options` 加可选 `write_mode`；设置页「基本」组只读展示。
- 启动器与任务页在 `legacy` 下给返回旧版的链接；不新增路由。
- 更新 `META-01` 与设置页用例。

### P6-03 备份与恢复

- `backup`：zip + `manifest.json`（文件数、字节、sha256、迁移头、写入者模式、排除项）。
- `restore`：默认 dry-run 打印差异；`--apply` 先校验 sha256，再解到临时目录、原子替换、保留 `pre-restore-*`。
- 回滚手册写进 `docs/upgrade/回滚手册.md`，按计划 8.8 八步编排，每步给可观测断言与预计耗时。

### P6-04 真实 Canary

- 人工批准、费用上限、单任务；`ACTIVE_ANALYSIS_UI=next`。
- 取证：任务详情事件流、`model_calls`、报告 `content_hash`、同一 `Idempotency-Key` 重放结果。
- 不达标就回退到 `legacy` 并在评审记录原因。

### P6-05 性能门禁

- `scripts/perf_core.py`：`vite preview` + 桩接口 + Playwright，PerformanceObserver 采 LCP/CLS，交互后采 INP。
- 两档视口各 20 样本取 p75；硬线 LCP 2.5s、CLS 0.1、INP 200ms；超线非零退出。
- 与 P4 的市场快照 p95、入口体积两条既有门禁并列，不互相替代。

### P6-06 双栈灰度与入口切换

- `scripts/stack_mode.py set legacy|next` 写 `.env.stack`；`run_all.bat` 读它决定起哪个入口。
- 切换前必须有一次备份与一次健康检查；切换后旧版仍能独立启动。
- 导航与设置页写明当前写入者与切换方法。

### P6-07 回滚演练与出口

- 演练八步：禁止新版创建 → 等终态或协作取消 → 切回旧版 → 验证兼容投影可读 → 保留新版只读入口 → 迁移不降级 → 数据损坏时恢复备份 → 不触碰交易日志。
- `e2e/e2e_p6.py` 聚合：构建与 bundle、Python 全量、P2–P5 回归、P6 E2E、性能三条线、迁移头、旧版冒烟、预检；单行 JSON，失败非零退出。
- 出口评审逐条对应四条判据，记录 R1、C4（P5 遗留）与本次演练结论。

## 4. 出口判据

P6 完成必须同时满足：

1. **回滚演练通过**：按 8.8 八步在备份副本上完整走通，真实目录只在人工确认后替换；演练前后 sha256 一致或差异可解释。
2. **Canary 无重复调用**：单次真实分析只执行一次模型图；同一 `Idempotency-Key` 重放不产生第二次调用。
3. **连续主用观察通过**：`next` 写入者连续运行一周，无重复执行、无报告字段丢失、无任务自动重跑。
4. **旧版可独立启动**：不依赖新版进程与 SQLite，旧报告可读。

门禁：预检 10 PASS；Python 全量不低于 789 passed / 4 skipped；前端单测不低于 527 条；入口 gzip ≤202.45 kB；P2–P5 E2E 全绿；迁移头随本阶段最后一票；axe critical/serious 0；LCP/CLS/INP 两档视口 p75 过线。

## 5. 风险

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 两个入口同时写导致报告覆盖 | 高 | 环境变量开关 + 重启切换；`legacy` 下新版提交被 409 拒绝 |
| 备份包含密钥或把 `~/.tradingagents` 全量入包 | 泄露/体积 | 排除项写进 manifest；密钥永不入包 |
| Canary 费用失控 | 中 | 单任务、费用上限人工批准、跑前跑后各记一次调用数 |
| 性能门禁受本机抖动 | 中 | p75 + 20 样本 + 目标线与回归线双线 |
| 回滚演练动到真实数据 | 高 | 在副本上演练；真实替换单独一步、需人工确认 |
| 契约新增错误码漏改哈希 | 中 | 同一次提交更新 `FREEZE-v1.md` 并跑预检 |
