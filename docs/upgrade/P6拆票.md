# P6 任务拆票：双栈灰度、性能与回滚

版本：v2（2026-11-07）
上游：`docs/upgrade/reviews/2026-11-07_P5出口评审.md` 结论为 Go；`p5-backlog.md` 第 7 节；计划书 8.5–8.8、9 节 P6 行与十四节发布清单。
用途：把 P6 拆成 9 张可独立验收的票（P6-00 至 P6-07，其中 04 拆为 04a/04b）。每票单独提交、单独回退、单独跑测试。

P6 收口双栈灰度：唯一分析写入者开关、备份与恢复、真实 Canary、一周主用观察、LCP/CLS/INP 门禁、默认入口切换与回滚演练。**观察期内默认入口仍是旧版 Streamlit；切换是 P6 的最后一步，由用户当场确认。**

## 0. 公共约束

- 技术栈不换：React 19 + TypeScript + Vite + TanStack Query；后端 FastAPI + SQLAlchemy + Alembic。
- 唯一写入者分两层：后端用 `ACTIVE_ANALYSIS_UI=legacy | next` 挡新版；旧版直接建图并写 `~/.tradingagents`（`web/runner.py`），后端管不到，只能靠启动脚本与端口互锁。**P6 的保证是端口级互锁加流程约束，不承诺防手动启动 `streamlit run`。**
- 默认入口：观察期内默认旧版；P6-07 在观察通过且用户确认后切换，旧版保留独立启动。
- 契约：按 `FREEZE-v1.md` 第 1 节，P6 允许「新增可选字段」与「新增错误码（不复用既有码含义）」，不升版本；但必须在同一次提交更新 `FREEZE-v1.md` 的哈希与当日评审理由，并同步测试。
- 迁移只做新增式，不要求降级；备份覆盖 SQLite 与 `~/.tradingagents` 的白名单部分。
- 不碰 `trade-journal` 仓库与其数据；不合并交易日志数据库。
- 后端不得 `import web.*`；测试不联网、不读 API Key、不读写真实 `~/.tradingagents`（Canary 与回滚演练除外，且必须显式 `--live`/`--restore` 才动真实目录）。
- `run_all.bat` 的边界仅在 P6-06 解除一次：只允许改成转调 `scripts/stack_launch.py`，改动不超过 5 行。
- 一票一本地提交，不推送；代码与证据分开提交。开工前与收工前预检必须 10 项 PASS。

## 1. 票内定稿

### 1.1 七项决定

**D1 开关只读一次，默认 legacy，切换必须重启**

`ACTIVE_ANALYSIS_UI` 在进程启动时读取一次并缓存；非法值启动即失败，不静默回退。默认 `legacy`。切换写入者必须重启后端，不做运行期热切换，避免两个入口同时拿到写权。

`stack_mode.py set next` 先检查 8501 是否在监听；在监听就拒绝，不写 `.env.stack`。`set legacy` 后必须重启后端并校验 `meta/options.write_mode == "legacy"`，校验失败就报错。

**D2 写入者状态由后端回答，前端不猜**

`GET /api/v1/meta/options` 新增可选键 `write_mode: "legacy" | "next"`（新增可选字段，不升版本）。这项契约改动放在 P6-01，与 409 同一次提交；P6-02 只做展示。

`tests/backend/test_meta_options.py` 的 META-01 从「恰好八个键」改为「八个既有键必在 + `write_mode` 可选」，逐键断言保留。FREEZE 第 1 节只把「新增测试」列为无需升版本，改 META-01 属于新增可选字段的必然结果，必须在同一次提交的评审记录里写明理由。

**D3 legacy 模式下的拒绝方式**

`legacy` 模式下新版 `POST /api/v1/jobs` 返回 `409 write_mode_legacy`，用户动作写「请在旧版发起分析」。新错误码写进 `error-codes-v1.md`，不复用 `active_conflict`、`idempotency_mismatch` 或 `illegal_transition`。

幂等顺序不变，且要写清：先查 `Idempotency-Key`；命中或已有同配置活动任务时照旧回放/返回既有任务，不产生写入；只有本来会新建任务时才 409。否则客户端丢响应后的重放会被误判失败。

**D4 备份是白名单快照，不是目录打包**

`scripts/backup_restore.py`：

- 数据库用 `sqlite3.Connection.backup()` 导出到临时文件，不停机也不拿撕裂快照；原因是 `jobs.db` 是 WAL 模式（`backend/app/core/db.py` 的 `PRAGMA journal_mode=WAL`）。
- 只收白名单：数据库快照、`logs/`、`exports/`、`memory/`、`job_reports/`、`incomplete_tasks.json`。
- `job_reports/` 是 P6-03 补入的白名单项：`backend/app/services/report_store.py` 把阶段报告与最终报告写在这里，与 `jobs.db` 的报告行一一对应；不收会在还原后丢失报告正文。
- 排除：`cache/`、`cache_ds_*/`、`logs_ds_*/`、`ds_run_console.log`、`llm_config.json`（含 `llm_base_url`）。
- zip 附 `manifest.json`：文件数、字节、sha256、迁移头、`ACTIVE_ANALYSIS_UI`、包含项与排除项。
- `restore` 默认 dry-run 打印差异；`--apply` 先校验 sha256，再解到同盘临时目录、按文件替换、保留 `pre-restore-*`。还原前必须停后端，Windows 下打开的 SQLite 文件无法替换。

**D5 Canary 一次、限额、可举证；通过后开始一周观察**

Canary 是一次人工批准的真实模型分析，费用上限由人工在 ticket 内写明。允许入口：`ACTIVE_ANALYSIS_UI=next` 且单任务。取证：任务详情的事件流、`model_calls` 与报告 `content_hash`；断言「同一 `Idempotency-Key` 重放不产生第二次模型调用」。

Canary 通过当天启动一周观察，由 P6-04b 每日审计，不靠人肉记忆。

**D6 性能门禁用构建产物，三条指标各两条线**

`vite preview` + 桩接口下用 Playwright PerformanceObserver 采样，手机档 390×844 与桌面 1440×900 各 20 样本取 p75。三条指标的目标线与回归线：

| 指标 | 目标线 | 回归线（超线即失败） |
| --- | --- | --- |
| LCP | 2.0 s | 2.5 s |
| CLS | 0.05 | 0.1 |
| INP | 150 ms | 200 ms |

INP 固定三个交互：手动刷新、市场到个股的路由切换、列表筛选；数据来自夹具，不联网。

**D7 切换与回滚都是脚本，不是手工步骤**

`scripts/stack_mode.py set legacy|next` 写 `ACTIVE_ANALYSIS_UI` 到 `.env.stack`；`scripts/stack_launch.py` 读它决定起旧版还是新版；`run_all.bat` 只改一行转调 `stack_launch.py`。回滚演练按计划 8.8 的八步执行，每步有可观测断言；演练前后各做一次备份并校验 sha256。

## 4. 出口判据

P6 完成必须同时满足：

1. **回滚演练通过**：按 8.8 八步在备份副本上完整走通，真实目录只在人工确认后替换；演练前后 sha256 一致或差异可解释。证据由 P6-07 产出。
2. **Canary 无重复调用**：单次真实分析只执行一次模型图；同一 `Idempotency-Key` 重放不产生第二次调用。证据由 P6-04a 产出。
3. **连续主用观察通过**：`next` 写入者连续运行一周，无重复执行、无报告字段丢失、无任务自动重跑。证据由 P6-04b 每日记录汇总。
4. **旧版可独立启动**：不依赖新版进程与 SQLite，旧报告可读。证据由 P6-06 与 P6-07 各验一次。
