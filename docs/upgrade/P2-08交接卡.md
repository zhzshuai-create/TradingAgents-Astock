## 四、契约行为

依据：`core-wireframes.md` 第 2 节 W02、`interaction-checklist.md` A01 至 A03、`api-v1.md` 1.3 与 1.8、`idempotency-conflicts.md` 第 1 节。

### 4.1 打开入口

- 工作台主按钮「开始分析」：打开空表单，URL 写 `?launch=1`。
- 工作台搜索选中：打开并预填，URL 写 `?launch=1&ticker=<code>`；深链直接打开同效。
- 股票占位页：给「开始分析」，跳到 `/workbench?launch=1&ticker=<code>`，复用同一入口。
- 任务重试入口在 P2-12 接入；本票把 `initialTicker`、`onClose`、`onCreated` 留成可复用 props。
- 打开、关闭、深链都只许读：最多 `GET /meta/options`、`GET /market/search`；不发 `POST /jobs`。

### 4.2 表单顺序

1. 标的：搜索框 + 已选「名称 代码」，可换票。中文名多命中列候选，不自动选。
2. 分析日期：默认 `meta/options.default_analysis_date`，不得按本地时区推导；不得晚于服务器当天。
3. 配置：模型配置取 `meta.llm_profiles`；并行分析开关；阶段开关默认收起，展开后逐项可关。
4. 费用提示：一句「分析会调用付费模型，预计 5–15 分钟」，不显示编造的价格。
5. 主按钮「开始分析」，次按钮「取消」；取消说明已发生的调用无法撤销。

### 4.3 提交分支

| 服务端结果 | 界面行为 |
| --- | --- |
| 201 新任务 | 关闭启动器，跳 `/jobs/:jobId`；任务列表与活动条失效重取 |
| 200 + `X-Existing-Job` | 跳该已有任务，提示「已有一个相同分析」；不新建 |
| 200 + `Idempotency-Replayed: 1` | 同一次意图的重放，按返回 job 跳转，不重复建任务 |
| 409 `active_conflict` | 表单内提示「该股票今日已有进行中的分析」，给「查看进行中的任务」（`details.active_job_id`）与「取消」；不提供强制新建 |
| 422 `ticker_unresolved` / `ticker_ambiguous` / `invalid_date` / `config_unknown_key` / `config_invalid_value` | 错误留在对应字段，已填内容不清空；`ticker_ambiguous` 列 `details.candidates`，`config_invalid_value` 可列 `details.allowed_values` |
| 429 `rate_limited` | 显示 `retry_after_ms` 折算的等待秒数；等待期内禁用提交 |
| 网络错误 | 保留表单，提示可重试；同一次提交意图复用同一把幂等键 |

提交中规则：

- 首次点击后按钮立即禁用并显示「提交中」；用 ref 守卫，避免同一帧内连点发出第二个请求。
- 409 提示里的「取消」只关闭冲突提示、回到可编辑表单；启动器自己的「取消」才关闭整个对话框。
- 成功后不得把 `?launch=1` 留在历史里，否则返回会再次打开启动器；用 `replace` 跳转或先清 query。

### 4.4 移动

- 桌面居中对话框；767px 以下全屏，单列，主按钮吸底。
- 阶段开关放全屏二级页或单一面板内的二级视图，不出现嵌套滚动。
- 触控项不小于 44px；390 与 360 无页面级横向滚动。

## 九、容易踩的坑

1. W02 写「展开后 7 个分析阶段可关」，但当前 `meta/options.stage_toggles` 只返回 3 项（`policy`、`hot_money`、`lockup`）。按服务端列表渲染，不硬编码 7；差异写进提交说明，要改先走解冻流程。
2. `parallel_analysts` 的默认值不在 `meta/options` 里，服务端 `ServerConfig` 默认 `true`。界面默认开启并显式提交布尔值，不要留空靠猜。
3. `default_analysis_date` 有 60 秒缓存，跨午夜可能过期；前端只做提示，最终以服务端 422 `invalid_date` 为准。
4. 连点只靠 `disabled` 不够：React 状态更新前的同一帧仍可能触发两次，必须加 ref 守卫。
5. 幂等签名只能用请求体；把 UI 状态（展开、提示、焦点）算进去会让同一意图换键。
6. 200 与 201 必须看响应头/状态，不能靠「job id 是不是新的」判断。
7. 启动器里的 `SearchBox` 不能沿用「选中即导航」：那会跳走并关掉表单。要么加 `onSelect`，要么 `TickerField` 直接用 `useStockSearch`。
8. `/workbench` 同时有顶栏搜索和工作台大搜索，可访问名会冲突；工作台用「搜索要分析的股票」，启动器内再用独立 label。
9. `Dialog` 目前没有移动全屏样式，面板自带滚动；要做吸底主按钮，需让 body 滚动、footer 固定，并保持焦点陷阱与 Esc。
10. jsdom 不执行媒体查询；移动全屏、吸底与 44px 由 E2E 覆盖，组件测试只测数据与文案分支。
11. 移动端纵向 flex 容易把 `flex-basis` 当高度；P2-07 已在搜索表单踩过，启动器同样要显式 `width: 100%` / `flex: 0 0 auto`。
12. `/jobs/:jobId` 是 P2-10 的占位页；本票只负责跳转，不要顺手实现详情。
13. 真实启动器打开会 GET `meta/options`（以及预填时的 `market/search`）；所有既有 MSW 测试都要补 handler，Playwright 桩要允许这些 GET。
14. E2E 里「打开再关闭零写」要排除 GET 干扰，只统计非 GET 请求。
15. 不要把服务端 200 重放当成错误；A02 的正常结果就是一次 201，后续点击被前端禁用拦下。
