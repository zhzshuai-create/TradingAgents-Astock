## 三、P4-11 交付了什么

- 间隔表：`frontend/src/lib/useVisibleRefetch.ts` 的 `REFRESH_INTERVALS` 从 `lib/query.ts` 的 `MARKET_STALE_MS` / `STOCK_STALE_MS` 派生，全站只有这一处毫秒表；组件只写 `usePolling(REFRESH_INTERVALS.*)`。
- 可见性：模块级 `useSyncExternalStore` 加单个 `visibilitychange` 监听，页面与页签共用；`refetchIntervalInBackground: true` 让后台标签页仍执行降频定时器。
- 降频：`document.hidden` 时间隔取 `max(base, 60_000)`；指数 10 s→60 s，行情 60 s 维持 60 s，行业 300 s 维持 300 s。
- 回前台：hidden→visible 时对 `["market"]` / `["stock"]` 作用域 `invalidateQueries({ refetchType: "active" })`，立即重取活跃查询。
- 手动刷新：trailing 500 ms 防抖，一次点击只发一组；卸载时清 timer。市场页按钮 `market-refresh`，股票页按钮 `stock-refresh`。
- 上下文：读者标题链到 `/stocks/:ticker`；任务桌面表 ticker 链到 `/stocks/:ticker`；股票头部两个上下文链接与市场→股票→返回沿用 P4-06/P4-09 的既有实现。
- 停表：查询观察者随页面卸载销毁，无需手写清账；E2E 用离开后 12 s 的 0 读取取证。

## 八、容易踩的坑

1. 预检第 1 项查工作区干净度：开工前必须 10 PASS；中途跑预检必然 FAIL，收工预检要在两次提交之后、工作区干净时复跑。证据 JSON 里的 `preflight` 写复跑结果，不写中途结果。

3. `stock_e2e.py` 的 390 首轮出现过一次 `pageerror`：等周 K `aria-pressed` 的轮询谓词在重渲染窗口解引用了空节点。谓词已改为 null 安全；出口脚本若新增 `wait_for_function`，先写 `node !== null &&`。
4. 移动端 `JobCards` 整卡是链接，不能再嵌 ticker 链接；`jobs_e2e.py` 断言卡片 `href == "/jobs/job-fail"`。ticker 回股票只在桌面 `JobTable`。
5. TanStack Query 默认暂停后台标签页定时器，`refetchIntervalInBackground` 必须为 true，否则隐藏降频根本不执行。
6. 组件测试读轮询间隔要用 `client.getQueryCache().find({ queryKey })?.observers[0]?.options.refetchInterval`，`query.options` 上没有该字段。
7. 假时钟与可见性覆盖要成对：`Object.defineProperty(document, 'visibilityState', ...)` 后手动派发 `visibilitychange`；每个用例后恢复，否则污染同文件其余用例。
8. Playwright 同步 API 里统计请求数必须用 `page.wait_for_timeout` 泵事件循环，`time.sleep` 会让回调不派发、断言恒为 0。
9. 出口脚本聚合子套件时直接解析子脚本最后一行 JSON，不要抓 stdout 的 PASS 行；子脚本的 `failures` 非空即整票失败。
