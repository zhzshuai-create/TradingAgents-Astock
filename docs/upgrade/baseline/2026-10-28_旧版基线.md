## 4. 待提交改动清单

工作区有 5 个已跟踪文件被改、1 个新测试文件未跟踪。内容聚成两组，性质不同，按组分开提交。

### A 组：K 线图口径修复

- `web/components/data_dashboard.py`（+90 / −27）
- `tests/test_kline_intraday_jump.py`（+79，新增 4 个用例）

改了什么：

1. 量价同色。收涨红、收跌绿、收平灰，量柱颜色与蜡烛方向严格一致。
2. 收平日（开盘价等于收盘价）补一层灰色蜡烛覆盖层，trace 名为 `flat-doji`。它加在成交量柱之后，这样既有测试锚定的 `fig.data[4]` 仍是量柱。
3. 成交量轴改成「万手」口径。源数据单位是股，除以 1e6 换算。刻度格式锁 `,.0f`，关掉 plotly 默认的 SI 缩写（"50M" 这类英文单位在 A 股语境不可读）。
4. 修了一个真 bug：主题桥里 `Plotly.restyle` 的 `marker.color` 必须嵌套成 `[[...]]`。不嵌套时整组颜色被按 trace 数拉链分发，单个 trace 只取元素 [0] 再广播成单色。这就是暗色主题下切换时全部量柱变成同一个颜色的根因。
5. 市场总览页的 30 日日均成交量文案同步改成 `/1_000_000`，与图表口径一致。

### B 组：冷加载与切页性能

- `tradingagents/dataflows/a_stock/_common.py`（+23）
- `web/data_functions.py`（+28 / −4）
- `web/app.py`（+12 / −4）
- `tests/test_page_switch_perf.py`（新增，145 行，未跟踪）

改了什么：

1. 核心层加 TDX bars 通道熔断。部分网络环境下 TDX 服务器连接正常、分时正常、日 K 恒空，每次冷拉白等 4 秒以上才落到新浪兜底。首次撞到空返回后熔断 1800 秒，期内 bars 请求直接走兜底链，到期自动放行重试。分时 `minutes()` 不受影响（实测健康，240 点 0.04 秒）。
2. web 层 `_get_kline_full` 尊重同一个熔断状态，不再自己重复白等。
3. 启动遮罩期间用守护线程预热探测一次 bars 通道，把这次空等消化在用户看到界面之前。异常全部吞掉，只写 debug 日志。
4. 顶栏模式切换去掉「写 session_state + `st.rerun()`」。原来一次切换要跑两轮全脚本（侧栏、顶栏、指数条、iframe 外壳各渲染两遍），是切页慢的主要来源之一。现在控件选中值当轮直接生效，`app_mode` 仍回写，只为兼容 dispatch 和既有读取方（包括测试里预置 `session_state["app_mode"]` 的写法）。
5. 个股估值看板五路数据改成并行拉取（腾讯行情、同花顺 EPS 预测、百度概念板块、K 线、东财新闻）。注释记录串行时冷加载 12 秒以上，K 线单路就要 9 秒；并行后由最慢一路决定。
6. 市场总览两路并行（东财行业排名约 2 秒、同花顺强势股约 0.4 秒）。
7. 骨架屏判定从「同一只股票只显示一次」改成「距上次完整加载超过 20 秒才显示」。暖加载（切周期、换主题）走缓存秒回，不闪骨架；冷加载仍然占位防白屏。

线程池与 Streamlit 缓存的关系已验证：`st.cache_data` 的缓存存储按进程 runtime 选择，worker 线程与主线程共用同一份缓存；线程里缺 `ScriptRunContext` 只影响 spinner 装饰，不影响缓存读写。

## 9. 界面与首屏耗时基线（2026-10-29 采集）

采集方式：旧版在隔离端口 8507 冷启动，Playwright 无头 Chromium，桌面 1440x900 与移动 390x844 两个视口。只读操作，未触发任何模型调用。采集脚本已入库为 `scripts/p0_baseline_shots.py`，新版对照时复用同一脚本，保证口径一致。
