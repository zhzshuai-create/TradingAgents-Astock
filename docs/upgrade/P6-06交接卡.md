### 2.1 `scripts/stack_mode.py`（新增）

| 命令 | 行为 |
| --- | --- |
| `status [--json]` | 打印 `.env.stack` 模式 + 8501/8600 监听 + 后端 `meta/options.write_mode`；一致退 0，不一致退 1 |

## 五、本机实测发现的坑

1. **系统 python 3.12 没有 streamlit**：原 `run_all.bat` 双击（未激活 venv）会 `No module named streamlit`。`stack_launch.project_python()` 改为优先 `.venv`。
2. **旧版写真实家目录**：`legacy_projection.default_logs_root()` 恒写 `Path.home()/.tradingagents/logs`，只隔离 `TA_DATA_ROOT` 不够；演练必须同时隔离 `USERPROFILE` / `HOME` / `RESULTS_DIR` / `CACHE_DIR`。
3. **桌面 `AStock-UI-dev.bat` 走另一条路**：它跑 `scripts/dev_backend.py`，`os.environ.setdefault(WRITE_MODE_ENV,"next")` 强制 next，**不读 `.env.stack`**，还固定占 8600。所以 `set`/launch 都必须先看 8600 是否被占。
4. **只杀自家后端**：早先只校验 `contract_version` 就能杀，实测会把用户 dev API 一起结束；现加命令行含 `run_backend.py` 的归属校验，活体验证：PID 45268 判定 `owned=False`，`set legacy` 退出 1，dev API 仍在。
5. **legacy 下 8501 没起只告警**：`set legacy` 会成功切换后端，但此时没有入口能发起分析，只打印 `[warn]`，不阻塞。

## 六、已知坑

1. Windows netstat 解析：只认 `TCP` + `LISTENING` + 冒号结尾端口，避免 UDP 与 IPv6 重复行。
2. PowerShell `Get-CimInstance` 有 ~1s 启动成本；命令不可读时按「非自家」处理，宁可拒绝。
3. `stop_backend` 轮询释放最长 25s；被防火墙/端口保留挡住时会报错而不是盲等。
4. `start_backend` 用 `DETACHED_PROCESS`，日志落 `%TEMP%\astock-stack\backend-<mode>.log`，失败先看它。
5. `.env.stack` 是进程启动值：切换后必须重启才生效，`status` 会明确报 mismatch 而不是假装一致。
6. 控制台 GBK：两个脚本入口都 `sys.stdout.reconfigure(encoding="utf-8")`。
7. 演练脚本在仓库外（`%TEMP%\astock-p6-06-drill\drill.py`），未入库；需要复跑时按本卡第四节重写，不要往仓库塞一堆一次性脚本。
