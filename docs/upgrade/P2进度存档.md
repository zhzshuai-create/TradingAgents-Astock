## 二、必须守的约束

- `TA_DEV_ROOT` 是环境变量，不在四个 CLI 开关里；E2E 用它隔离数据。
- `--stage-delay-ms` 在阶段 done 后 sleep，默认 0，不改 `tests/fake_analysis_graph.py`。

- uvicorn 已在 backend extra 声明，并在 `constraints.txt` 锁定 0.54.0（h11 0.16.0、click 8.5.0）。
- 新前端仍是开发态，不接管旧版默认启动；旧版 8501 仍是默认写入口。

- 错误文案只从 `ApiError.message` 或 `displayErrorMessage()` 取；不得把响应体、异常对象、堆栈或路径直接渲染。
- 幂等键属于「提交意图」而非组件生命周期：同一表单（含键顺序不同）与网络错误后的重试复用同一个键，任何字段变化或 `reset()` 后换新键。
- `meta/options` 的 `staleTime` 与 `gcTime` 都是 60 秒；任务详情 `staleTime = 0`，不使用长缓存。
- `/api/v1/jobs` 与 `/api/v1/meta/options` 都是只读：列表不触发对账、不改状态、不发事件；元信息不读任务表，探活不拉起日志服务、不写任何文件。

## 三、P2-01 至 P2-08 的取舍与遗留

- 组件只用语义令牌，基础色阶只在 `tokens.css` 内部互相引用；WEB-01 的十六进制扫描覆盖 `src` 下 `.ts/.tsx/.css`。
- Dialog/Drawer 用自建焦点陷阱，不依赖原生 `<dialog>`：jsdom 对 `showModal` 的支持不可靠，E2E 前也无法保证焦点语义。
- 开发入口把 uvicorn 放在线程、由主线程安装信号处理。原因：uvicorn 的 `capture_signals` 会在优雅退出后重发 SIGINT/SIGBREAK，若让 uvicorn 占主线程，进程退出码和租约释放都不受控；DEV-01/DEV-03 依赖退出码 0 与租约即时释放。
- Worker 拿不到全局租约时每秒重试，崩溃重启不必等人工；启动对账仍只在首次拿到租约后跑一次。
- 未做（按票交给后续）：任务列表与详情页（P2-09、P2-10）、SSE（P2-11）、重试与续跑的真实写操作（P2-12）；活动任务条的「还有 N 个」完整跳转与 A04 返回路径放到 P2-13。
- P2-02 的主题切换已完成并写 `localStorage`；顶栏与移动「更多」抽屉都有入口，`data-theme` 落在 `<html>`。
- E2E 用独立脚本 `e2e/shell_e2e.py`，不用 pytest：`.venv` 没有 Playwright，系统 Python 3.13 有。脚本自己构建、起 `vite preview`、结束后必须等到抽屉动效再截图，否则会截到滑入中间帧。
- jsdom 不为 `display:none` 的元素计算可访问名，底栏角色查询会在名称过滤上失败。WEB-03 用 `data-testid="mobile-nav"` 定位底栏，再按文本取链接与「更多」按钮。
- 移动端 44px 只加在 `@media (max-width: 767px)` 的 Button 上，桌面按钮仍保持 34px 密度；搜索提交按钮单独设最小高度。
- P2-02 的视觉走查已用 1440/390/360 截图完成，截图在 `ui_shots_p2/P2-02/`（`ui_shots_*/` 不入库）。
- 目录默认源只读：`_common._cache_dir()` 会 `makedirs`，P2 的目录读取自己拼路径，缺失直接返回 `upstream_error`；绝不在请求里重建全市场，也不联网。
- P2-03 不给详情与 SSE 加名称回填：只在 `job_detail` / `job_summary` 上提供能力，避免 REST 详情与 SSE snapshot 不一致。P2-04 的列表路由调用 `job_summary(..., ticker_directory=...)` 才算接线。
- 无命中返回 `ok` + 空 `items`（数据源正常应答）；只有空 q 才是 `empty`，因为契约 3.0 的 `empty` 语义是「今天没有数据」。
- 磁盘名称表超过 24h 返回 `stale` + `ttl_exceeded`（契约 3.0 的搜索阈值），仍带 items；静态 fixture 的 `as_of` 是取数时刻，不会 stale。
- 搜索条数上限是契约空白：本阶段默认 10、上限 50，写进提交说明 `9198d5b`，要改先走解冻流程。
- 加载失败缓存 30 秒，避免无缓存时每个请求都 stat 磁盘；`name()` 永不抛错，目录故障不影响任务读取。
- 搜索测试用桩 service 建 app，SRCH-04 断言临时目录里没有库、报告目录或任何新文件。
- 列表游标是 `created_at + \x1f + job_id` 的 base64url（去尾 `=`），严格校验字母表；解码失败才是 400，格式正确但已无后续行返回空页而不是报错。
- 一页列表固定 5 条 SELECT：任务页、阶段行、阶段时长事件、每任务最大 stats 事件、对账备注；不按任务逐条查。`next_cursor` 只在多取到第 `limit+1` 行时返回。
- `active` 与 `status` 的互斥按参数是否出现判断（含 `active=false`），错误一律指向 `details.field=active`；`active=false` 单独出现等价于不过滤。
- 列表契约未定义 `limit<1`，按 1 截断，与 market/search 取值规则一致；契约也未定义 `date_from > date_to`，返回空页不报错。
- 列表沿用 P2-03 的 `JobSummary = JobDetail - stages`，因此带上 `reconcile_notes`（批量查，列表与同任务详情除 stages 外仍一致）。
- 本机防火墙丢弃回环端口 SYN：关闭的 8502 表现为超时而非拒绝，所以连接拒绝与超时都判 `not_running`；`probe_failed` 只表示「端口有应答但身份不是交易日志」或探活自身异常，与线框 W09 的「端口被其他服务占用」对应。

- 控制动作的查询失效放在 `lib/query.invalidateJobQueries()`，由 P2-12 的动作 hook 调用；`api/jobs.ts` 不依赖 React Query，保持纯请求层。

- 工作台搜索目标与 `routes.md` §3 的通用「进股票页」冲突：按 P2-06 票与 W02 线框，仅 `/workbench` 进启动器（`/workbench?launch=1&ticker=`），其他页面仍进 `/stocks/:code`。写进提交说明 `fc2cae4`，要改先走解冻流程。
