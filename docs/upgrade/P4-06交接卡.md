## 三、P4-06 交付了什么

- `/market` 从占位页换成真实看板：`pages/MarketPage.tsx` 只做路由转出，保留 `page-market`。
- 市场状态条：`market_session` 中文（未开盘/交易中/午间休市/已收盘）+ 最近更新时间 + 来源中文名。
- 指数三卡：价格、涨跌幅、涨跌额、数据时间、来源；涨红跌绿沿用 A 股口径。
- 行业表：服务端返回的涨幅前 N（默认 20，可切 10/30）与末位若干，列排名、行业、涨跌幅、上涨/下跌、领涨股；整行可点，行业名按钮也可点。
- 成分股抽屉：右侧 10 家，标题为「行业名 · 成分股」；行链接 `/stocks/:code?tab=valuation`；关闭清 `board`。
- 强势股：表格 5 列；题材从 `reason` 聚合 TOP8，加「全部」芯片，点击只筛当前列表；空列表显示「非交易日或盘后未更新」。
- 快讯：纯文本列表；只把 http(s) 子串转锚点，尾部中英文标点剥离；新窗口 + `rel="noopener noreferrer"`。
- 状态：四块各自 `DataState`；partial 显示失败块中文名；stale 显示原因横幅；每块独立重试。
- URL 状态：`top`、`date`、`board`、`theme` 为唯一状态源；非法/越界静默回默认，路径不改写，加载时不 replaceState。
- 返回现场：点击捕获 + popstate 保存滚动，`history.state` 标记 + sessionStorage 恢复；从股票返回恢复行业、topN、日期、抽屉、滚动 5 项；刷新回顶部。

## 八、容易踩的坑

1. 行业区块标题「行业排名」与控件可见标签同名会让 `getByLabelText` 命中 section 的 aria-labelledby 与 label 两处；控件标签已改成「显示条数」，测试与 E2E 都按这个取。
2. 成分股是异步查询：`findByTestId` 前不要同步 `getAllByTestId`；E2E 用 `wait_for_function` 等 10 行到位。
3. 题材筛选要断言「当前列表」而不是总数：切到算力后只应剩 3 行，点「全部」后 URL 不再带 `theme`。
4. 返回恢复的保存键必须与恢复时的 `pathname+search` 完全一致；`toMarketSearch` 的字段顺序是 `top,date,board,theme`，点击捕获时用旧键、点成分股时用新键，这是设计行为。
5. 刷新不能恢复滚动：靠 `PerformanceNavigationTiming.type === "reload"`；E2E 的 `page.reload()` 后断言 0。
6. 状态流里的「error」用 HTTP 200 信封 `status=error`，不要用 500；否则浏览器会打资源错误，和「1440 无控制台错误」互斥。
7. `check_bundle.mjs` 默认写 P4-04 拆包证据；本票用 `--out` 临时文件。`e2e_p3.py` 仍会改写 P3-09 性能证据，复跑后 `git checkout --` 还原。
8. `e2e/market_e2e.py` 首次运行有过一次 `wait_for_url` 后立即 `is_visible` 的竞态，已改成先等 `page-stock` 可见；新增断言沿用「先等可见再断言」。
9. 390/360 下当前仍是桌面表格包在 `overflow-x:auto` 容器里，页面不横滑但可容器内滑；P4-07 才把它换成卡片，不要提前做成两套布局。
