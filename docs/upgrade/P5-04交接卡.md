## 五、口径

### 5.1 三态与进入条件

```ts
type JournalView = "available" | "starting" | "unavailable";
```

- `available`：`meta.journal.available === true` **且** `entry_url` 可解析为 `http/https`。
- `unavailable`：`available === false`；按 `reason` 分支；`reason === null` 按 `probe_failed` 处理，不新增状态名。
- `starting`：只在用户点「已启动，重试」后进入的**前端本地态**，不是服务端状态。
- `entry_url` 非法或协议不是 `http/https`：按 `unavailable` 处理，不渲染 iframe，新窗口按钮也不出现。
- 首次进入页面**不自动**进入 `starting`；只显示 `meta` 给出的当前状态。

### 5.2 启动中轮询

- 点「已启动，重试」→ `starting`，立即 `refetch()` 一次，然后每 2000ms 重取，最多 30s。
- 任一成功响应 `available === true` → 切 `available` 并停止轮询。
- 30s 仍未可用 → 停止轮询，回 `unavailable`，沿用最后一次 `meta.journal.reason`（空则 `probe_failed`）。
- 卸载、切到 `available`、用户取消都要清理定时器；离开页面后不再有 meta 请求。
- 不复用 `usePolling`（它是页面可见性降频表，语义不同）；用局部 `setInterval` + 清理。

### 5.3 三套原因文案与下一步

统一说明句：「交易日志是独立应用，当前没有在运行。」

| reason | 追加指引 | 禁止 |
| --- | --- | --- |
| `not_running` | 给 `trade-journal/run.bat` 启动命令与「已启动，重试」 | 不自动执行、不代跑 |
| `not_installed` | 给目录缺失与安装说明 | 不显示启动命令 |
| `probe_failed` | 提示端口可能被其他服务占用，给检查步骤（端口、代理绕过） | 不猜「服务崩溃」 |

- 三套都显示「本系统不会读取或修改交易日志的数据。」
- 「重试」只是重新进入 `starting`，不刷新整页。

### 5.4 主题桥

```ts
const journalOrigin = new URL(entry_url).origin; // 仅 http/https
```

- 发送：iframe `load` 时与主题变化时 `iframe.contentWindow?.postMessage({ type: "astock-theme-request", theme }, journalOrigin)`；**不用** `"*"`。
- 监听：`event.origin === journalOrigin` **且** `event.source === iframe.contentWindow` **且** `event.data?.type === "astock-theme-request"`，三者缺一即忽略；外来 origin 不回消息。
- 卸载时移除监听；iframe 重建时重新绑定。
- 旧版与 `trade-journal` 的宽松桥不在本票改，记入遗留。

### 5.5 布局

- 可用态：页面头部一行「日志服务运行中」+「新窗口打开」（`target="_blank"`、`rel="noreferrer"`）+「刷新」（`iframe.src` 重新赋值或 key 递增）。
- iframe 容器高度 `calc(100dvh - 顶栏 - 间距)`，iframe `width/height: 100%`、`border: 0`。
- 移动端 `/journal` 页面自身不滚动：`#main-content` 在该页锁定溢出，只保留 iframe 内部滚动，容器 `overscroll-behavior: contain`。
- 不可用/启动中：普通说明页滚动，不做锁滚动；360/390 不得出现页面级横向溢出。
