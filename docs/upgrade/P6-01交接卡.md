## 五、口径

### 5.1 开关与默认值

- 环境变量：`ACTIVE_ANALYSIS_UI`，合法值只有 `legacy` 与 `next`。
- 默认：`legacy`。`load_server_config()` 在进程启动时读一次并放进 `ServerConfig`；运行期不再读环境变量。
- 非法值：`None` 以外的空串、拼写错误、大小写混写以外的任何值都必须启动失败。建议 `parse_write_mode` 只接受去空格后的小写精确值，空串也算非法；`None` 才走默认。
- `ServerConfig.write_mode` 的 dataclass 默认值也是 `legacy`。**不要为了省测试改动把默认值改成 `next`**；测试与脚本要建任务就显式传 `write_mode="next"`，这是本票的 fail-closed 保证。
- `write_mode` 不参与 `config_defaults()`，不参与 `config_hash`；它只是服务端开关，不是用户配置。

建议的 `write_mode.py` 形状：

```python
WRITE_MODE_ENV = "ACTIVE_ANALYSIS_UI"
WRITE_MODES = ("legacy", "next")
DEFAULT_WRITE_MODE = "legacy"

def parse_write_mode(raw: str | None) -> str:
    if raw is None:
        return DEFAULT_WRITE_MODE
    value = raw.strip().lower()
    if value not in WRITE_MODES:
        raise ValueError(
            f"{WRITE_MODE_ENV} must be one of {WRITE_MODES}, got {raw!r}"
        )
    return value
```

`load_server_config()` 里传 `parse_write_mode(os.environ.get(WRITE_MODE_ENV))`。`create_app()` 在启动时构造 `ServerConfig`，非法值会直接抛出；不需要额外的健康检查。

### 5.2 创建路径与判定顺序

- 两条新建入口都汇到 `JobService._create_once`：`create_job`（`POST /api/v1/jobs`）与 `retry_job`（`POST /api/v1/jobs/{id}/retry`，`job_service.py` 的 `retry_job` 在第 526 行调用 `_create_once`）。开关加在 `_create_once`，两条路径自动覆盖。
- 位置：在第 3 步（同配置活动任务）与第 4 步（不同配置冲突）之后，`job = Job(...)` 之前。命中前四步时照旧返回，不 409；只有本来会新建时才 409。
- 五步契约顺序不变：1 幂等命中回放；2 键相同体不同 409 `idempotency_mismatch`；3 同配置活动任务 200；4 不同配置活动任务 409 `active_conflict`；5 新建。写入者开关是第 5 步的前置条件，不改前四步。评审记录要写明这句话。
- 409 写法：`raise JobCreateError("write_mode_legacy", status_code=409)`；`errors.py` 的 `CODE_STATUS` 加 `"write_mode_legacy": 409`，`CODE_MESSAGE` 加「当前由旧版发起分析，请到旧版入口开始分析」。
- `_settle_after_race` 不插入新行，只回放/返回/抛冲突，不需要加开关；不要在那里重复判断。
- 重试也算新建：`retry_job` 的 docstring 明确「retry/resume always creates a new job」。因此 `legacy` 下重试也 409。
- 控制动作不拦：`pause`、`cancel`、`resume` 不创建新任务，保持原行为。回滚演练第 2 步用「等终态或协作取消」处理在跑任务，不靠本开关。

### 5.8 失败处理

- 全量测试出现 409：先定位是哪个 fixture 没声明 `next`，补调用点。
- CT-08 失败：用测试里的算法重算两份哈希；检查文件是否被写成无 BOM 或 LF。
- 前端旧 mock 失败：确认 `write_mode` 在 TS 类型里是可选的，且 UI 只在显式 `legacy` 时禁用。
- `meta/options` 其他断言失败：确认没有把 `write_mode` 写进 `limits` 或 `journal`，它必须是顶层键。
