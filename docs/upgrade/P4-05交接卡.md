## 八、容易踩的坑

1. 报告行与 ticker chip 会同时出现同一股票名；测试取文本要限定行内，否则 `getByText` 命中多个。
2. 工作台有两个「查看全部」链接（最近任务、最近报告）；E2E 需按区块 scope，否则 strict mode 报错。
3. 三块市场摘要各自重试，不要把顶层 query 合成一个；WB-02 断言了“点一块不影响其他块”。
4. `DataState` 的 `skeletonHeight` 必须与内容高度同源，否则 DS-04 的口径破坏；本票三块用 96 px。
5. `check_bundle.mjs` 默认写 P4-04 拆包证据；测 P4-05 时用 `--out` 指到临时文件，或测完 `git checkout --` 还原，别把旧证据改脏。
6. `e2e/e2e_p3.py` 会改写 P3-09 性能证据 JSON；复跑后要还原，不随本票提交。
7. `job_actions_e2e.py` A09 等待“运行中”偶发超时（本机已见一次）；单独复跑能过，与工作台改动无关，不要为此改产品代码。
8. 路由懒加载下 E2E 要等待 `page-*` 或组件 testid，不要立即取 `h1`。
