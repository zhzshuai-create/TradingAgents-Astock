## 三、P4-08 交付了什么

- 几何层：价格/成交量映射、平盘域撑开、nice ticks、可见窗口、槽宽、索引↔x、锚点缩放、两端夹紧、日期标签采样、时间轴（09:30=0 至 15:00=330）、午休断点。全部是纯函数，没有 React 与 DOM。
- K 线：蜡烛（涨红跌绿、十字星灰）+ 成交量副图 + 价格刻度 + 日期刻度；日/周/月按钮只回调 `onPeriodChange`，换数据后窗口与刻度重算；默认显示全部已加载 bar，可用 `initialCount` 收窄。
- 缩放平移：滚轮以指针所在 K 线为锚点缩放，最少 10 根；拖拽按 bar 宽度折算位移，两端自动夹紧；触控指针不进拖拽，把横滑让给容器。
- 十字光标：吸附最近 K 线，显示日期/开高低收/涨跌/量/额；指针离开回到最后一根。`data-snapped` 标记当前是否吸附。
- 图例：K 线与成交量可分别开关，按钮 `aria-pressed` 反映状态。
- 标注：不复权标签（`data-adjust`）、数据时间（`asOf` 优先，缺失回退 `fetchedAt`）、`1–N / total 根` 窗口提示。
- 分时：价格线 + 均价虚线 + 成交量；按 `session_gaps` 与 `avg_price=null` 分段，午休带可见；时间轴固定 09:30/11:30/13:00/15:00；十字光标吸附最近点；三个图例可分别开关。
- 空/单点/缺失：空 `bars`/`points` 显示 `EmptyState` 且不画 SVG；单根/单点走圆点分支，不产生 NaN；`amount=null` 显示「—」，不用 0 冒充。
- 移动：所有按钮 44 px；SVG 最小宽 640，外层容器 `overflow-x:auto` + `min-width:0`，横滑只在容器内，页面级不溢出。
- 测试可断言：几何与状态全部落在 `data-*` 上，jsdom 不需要 canvas 或真实像素。

## 八、容易踩的坑

1. React 的 `onWheel` 是 passive，`preventDefault` 无效；缩放必须用 `addEventListener("wheel", ..., { passive: false })`，并在卸载时移除。
2. jsdom 的 `getBoundingClientRect()` 全是 0；事件坐标换算要按 `rect.width > 0` 兜底，否则除零得到 NaN。组件测试只断言 `data-*` 与元素数量，不断言像素。
3. 分时图也有 `data-role="volume-bar"`；浏览器断言 K 线成交量必须限定 `svg[data-chart="kline"] [data-role="volume-bar"]`，否则数量永远不为 0/8（本票实际踩到，产品无误）。
4. 时间轴首尾标签用 `text-anchor: middle` 会在 09:30 和 15:00 被 SVG 边缘裁掉；首标签改 `start`、末标签改 `end`。
5. 蜡烛体宽上限 14 px 在周 K 只有 8 根时显得过细；上限调到 24 px。改的是观感，不影响任何断言。
6. 触控指针不参与 K 线拖拽（`pointerType === "touch"` 直接返回），横滑交给容器；移动端没有双指缩放，也不要加，P4-10 的口径是「周期按钮 + 容器横滑」。
7. `matchMedia` 在 jsdom 不可用；本票组件不依赖视口，测试无需桩，移动尺寸只在浏览器探针里验证。
8. 全量 vitest 并行时 AppShell 路由用例会超过默认 1 s；不要靠复跑掩盖，直接在该用例把查询超时调到 4 s。
9. `e2e/e2e_p2.py` 的 `job_stream_e2e.py` A05 有 SSE 帧与详情渲染的竞态：阶段已显示「已完成」但 `sessionStorage` 里还没有游标，断言 `cursor=None`。单跑与随后全量复跑均通过；遇到先复跑，不要改该套件。
10. 运行 `e2e/e2e_p3.py` 会改写 `reviews/2026-11-06_P3-09性能结果.json`，跑完必须 `git checkout --` 还原；`check_bundle.mjs` 用 `--out` 写临时文件，别覆盖 P4-04 证据。
