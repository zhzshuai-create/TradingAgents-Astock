AStock Pro 专业投研工作台全面升级计划

日期：2026-10-28
版本：评审稿 v1.0
范围：产品、交互、视觉、前端、后端任务系统、报告、数据服务、迁移与交付
现状基线：TradingAgents-astock 当前工作树及 2026-10-27 前端优化记录

先说结论

这次升级不应只更换界面皮肤。

目标是把 AStock Pro 从“Streamlit 驱动的分析页面”升级为“以股票为中心、任务可恢复、报告可追溯的个人专业投研工作台”。

推荐技术路线是：

  • 前端采用 React + TypeScript。
  • 后端采用 FastAPI。
  • 分析引擎继续使用现有 tradingagents。
  • 分析任务交给独立单 Worker 执行。Worker 是单独运行的后台执行进程。
  • SQLite 保存任务、事件、报告索引和设置。
  • SSE 推送任务进度。SSE 是浏览器持续接收服务端消息的单向通道。
  • 旧 Streamlit 保留为独立回退版本。
  • 交易日志继续保持独立应用和独立数据，不在首期合并数据库。

整个项目最难的部分不是 React 页面。

最难的是分析任务在刷新、崩溃、重连、暂停和重试时，仍能避免重复模型调用，并如实表达任务状态。

计划优先保证费用安全和数据可信。

遇到无法确认的崩溃现场，系统应标记“已中断，等待人工处理”，而不是自动重跑。

按 1 名熟悉项目的开发者全职投入并配合 AI 辅助估算，完整替代旧版需要 15–21 人周。

完成“分析 + 任务 + 报告”内部可用版本，预计需要 8.5–12 人周。

一、现状评估

1.1 已经具备、应当保留的资产

多智能体分析引擎

现有引擎已经包含七类分析师、多空辩论、交易决策、风险评估和最终信号。

核心图不依赖 Streamlit，具备直接复用条件。

本次不重写提示词、辩论逻辑和信号算法。

A 股数据能力

项目已有行情、K 线、估值、概念、行业、强势股、北向资金、资金流和资讯等数据能力。

数据层已有缓存、重试、节流和部分降级机制。

新后端应复用这些能力，而不是让前端重新对接各个数据网站。

报告与导出

现有报告已覆盖阶段报告、多空辩论、风控和最终决策。

Markdown 与 PDF 导出已有实现基础。

本次重点解决报告版本、阅读体验和导出副作用，不重新设计报告内容体系。

交易日志

交易日志是独立产品，具备独立的数据和业务流程。

现有 iframe 集成保持了较低耦合。

首期保留这个边界，只升级导航、状态、尺寸、主题和故障反馈。

测试与恢复机制

项目已有 Python 测试、Streamlit AppTest、浏览器验收脚本和移动端截图基线。

这些资产应继续作为旧版回归门禁，并转化为新旧语义对照测试。

1.2 当前制约专业工作台的六类问题

问题 当前表现 升级方向
信息架构分散 侧栏、首页和报告页存在重复入口，能力还不完全一致 建立统一导航、统一分析启动器和 URL 驱动的工作区
任务生命周期不可靠 任务依赖进程内字典和 daemon 线程，服务重启后无法可靠恢复 数据库任务、独立 Worker、持久事件和明确状态机
报告会被覆盖 同股票、同日期报告使用相同文件键 每次分析生成独立报告版本
数据状态不清楚 空数据、请求失败和缓存陈旧经常表现相同 统一数据状态、来源、业务时间和抓取时间
阅读与移动体验不足 长报告定位弱，移动目录和日志嵌套滚动不完善 专业报告阅读器、移动抽屉和单滚动容器
页面存在隐藏成本 打开报告即生成 PDF，PDF 又可能重新拉取行情 报告读取零导出副作用，PDF 显式生成并缓存

1.3 升级的核心矛盾

React 替换本身风险可控。

真正需要优先处理的是以下四件事：

  1. 任务必须有独立 ID，不能只属于某个浏览器会话。
  2. 每个任务必须保存不可变配置快照。
  3. 每次成功分析必须保留独立报告版本。
  4. 任何刷新和断线都不能自动创建新的付费分析。

因此，实施顺序必须是“任务与数据地基 → 新界面 → 双栈切换”，不能先做完整新皮肤再补后端。

二、产品定位与范围

2.1 产品定位

AStock Pro 是面向个人 A 股研究者的本地专业投研工作台。

它以股票为研究对象，把以下流程连成一条连续主线：

市场发现 → 股票工作区 → 发起 AI 分析 → 跨页跟踪任务 → 阅读版本化报告 → 导出与复盘 → 跳转交易日志

它不是自动交易系统。

它也不以堆叠更多指标为目标。

它的核心价值是研究上下文不丢失、任务状态可信、报告可以追溯、数据时效可以判断。

2.2 设计原则

主线唯一

“新建分析”可以出现在多个页面，但所有入口必须打开同一个分析启动器。

不同入口不得各自实现一套任务创建逻辑。

股票上下文连续

用户从市场、任务或报告进入同一股票时，应看到一致的股票头部和相关研究内容。

返回来源页面时，恢复筛选、展开状态和滚动位置。

状态必须真实

“暂停中”不能显示为“已暂停”。

“取消请求已提交”不能显示为“已停止”。

“连接中断”不能被描述成“任务失败”。

付费动作明确

只有用户明确点击才能创建分析。

打开 URL、刷新页面和 SSE 重连都不能触发新任务。

重新分析和检查点续跑必须使用不同文案。

数据必须带时间口径

每个市场数据区块都要能回答三个问题：数据来自哪里、数据本身属于什么时间、系统何时取得它。

移动优先保证主任务

移动端不追求复制桌面全部信息密度。

移动端首先保证搜索、任务跟踪、报告阅读和关键控制可用。

2.3 首期交付范围

  • 全新工作台首页。
  • 市场看板。
  • 股票工作区。
  • 统一分析启动器。
  • 任务中心和任务详情。
  • 报告库和版本化报告阅读器。
  • Markdown 与 PDF 按需导出。
  • 交易日志整合外壳。
  • 模型与界面设置。
  • 旧报告和旧未完成记录迁移。
  • 旧 Streamlit 双栈运行、灰度和回滚。
  • 桌面与移动端完整验收。

2.4 明确不做

  • 不调整 Agent 数量、提示词和默认辩论轮次。
  • 不承诺相同输入产生逐字一致的模型结果。
  • 不接券商下单、自动交易和实盘账户。
  • 不合并交易日志数据库。
  • 不把交易日志业务重写为 React 子模块。
  • 不引入微服务、Kubernetes、Redis、Celery 和多 Worker 集群。
  • 不做组织、角色、多人协作和复杂权限。
  • 不做 tick 级行情、Level-2 和低延迟全市场推送。
  • 不自动重试可能已经产生模型费用的中断任务。
  • 不把报告对比、关注列表和复杂通知中心列为首个完整版本的阻塞项。
  • 不尝试恢复已经被旧文件覆盖的历史报告版本。

三、目标信息架构

3.1 桌面端结构

采用“左侧导航 + 顶部研究工具条 + 主内容区”。

左侧导航

展开宽度建议 232px，折叠宽度建议 72px。

导航项如下：

  1. 工作台
  2. 市场看板
  3. 股票工作区
  4. 任务中心
  5. 报告库
  6. 交易日志
  7. 设置
  8. 旧版入口

“股票工作区”没有当前标的时，展示最近研究股票和搜索入口。

顶部研究工具条

包含：

  • 全局股票搜索。
  • 当前活动任务入口与数量。
  • Worker 和数据服务状态。
  • 亮暗主题切换。
  • 当前页面需要的轻量操作。

顶栏不再重复展示大面积品牌卡和模型说明。

模型详情移入设置页或紧凑状态弹层。

3.2 移动端结构

顶部保留返回、页面标题、搜索和活动任务状态。

底部设置五个入口：

  • 工作台
  • 市场
  • 任务
  • 报告
  • 更多

“更多”包含交易日志、设置和旧版入口。

移动端侧栏不默认展开。

关键触控区域至少 44 × 44px。

360px 宽度下不得依赖页面级横向滚动。

3.3 建议路由

/workbench
/market
/stocks/:ticker?tab=overview|news|reports
/jobs
/jobs/:jobId
/reports
/reports/:reportId?section=...
/journal
/settings

股票、筛选、分页、任务 ID 和报告章节应体现在 URL 或路由状态中。

URL 只负责定位，不负责自动执行付费动作。

3.4 四条核心用户流程

从市场发现到研究报告

市场看板点击股票 → 进入股票工作区 → 点击“发起 AI 分析” → 确认配置 → 进入任务详情 → 完成后进入报告。

直接分析

全局搜索股票 → 打开统一启动器 → 检查相同活动任务 → 创建或复用任务 → 跨页持续跟踪 → 阅读报告。

历史研究与重跑

报告库筛选 → 打开指定版本 → 查看同标的其他版本 → 选择“使用相同参数重新分析” → 创建新任务和新报告。

旧报告不被修改。

异常恢复

浏览器刷新后按任务 ID 重新读取快照并订阅进度。

SSE 断线后显示连接状态并自动重连，不重启任务。

Worker 崩溃后任务标记为“已中断”。

只有存在匹配检查点时，才提供“从检查点继续”。

否则只提供“重新分析”。

四、页面与交互详细设计

4.1 工作台首页

页面目标

让用户在首屏完成两件事：开始研究，以及回到尚未完成的研究。

首屏布局

  1. 股票搜索框。
  2. “新建分析”主按钮。
  3. 当前活动任务。
  4. 最近报告。
  5. 最近研究股票。
  6. 精简市场摘要。

删除或迁移的内容

  • 删除占据首屏的名言区。
  • 删除重复的侧栏新建分析表单。
  • 删除大段版本和流程说明。
  • 将系统状态压缩为状态入口。
  • 将完整模型配置移入分析启动器和设置页。

活动任务卡

显示股票、分析日期、当前阶段、真实状态、耗时和“继续查看”。

失败任务显示“查看错误”和“重新分析”。

中断任务显示“等待人工处理”，不能继续显示“进行中”。

最近报告

显示股票、分析日期、信号、生成时间和报告版本。

点击后进入指定报告，不再通过临时 session 状态间接打开。

验收重点

首屏主操作明确。

活动任务和最近报告无需展开隐藏面板即可看到。

跨页返回后，首页不重复启动任何任务。

4.2 统一分析启动器

打开入口

工作台、股票工作区、任务重试和报告重跑都使用同一启动器。

桌面端使用右侧抽屉或居中对话框。

移动端使用全屏页面。

表单顺序

  1. 股票与分析日期。
  2. 模型供应商和模型组合。
  3. 并行分析师等高级选项。
  4. 本次配置摘要。
  5. 明确的提交按钮。

提交规则

点击后按钮进入提交中状态，防止重复点击。

服务端仍必须通过幂等键防止重复创建。幂等指同一个请求重复到达时只产生一次实际任务。

相同幂等键和相同请求体返回原任务。

相同幂等键但请求体不同返回冲突。

同股票、同日期、同配置已有活动任务时，直接提供“查看已有任务”。

同股票、同日期但不同配置仍有活动任务时，提示冲突，不静默排队。

付费提示

提交前说明本次会启动真实模型调用。

重试时说明这是新任务，可能产生新费用。

取消时说明已经发生的调用无法撤销。

4.3 股票工作区

固定股票头部

显示代码、名称、最新价、涨跌幅、数据来源和数据时间。

缓存陈旧时显示明确标记。

主操作包括“查看最新报告”和“发起分析”。

当前已有同标的任务时，主按钮改为“查看进行中任务”。

内容分区

  • 概览：价格、估值、市值、换手率、K 线和成交量。
  • 估值与题材：EPS 一致预期、前向估值、行业、概念和地域。
  • 资讯：个股新闻与相关快讯。
  • 研究报告：该股票全部报告版本。

加载方式

各区块独立加载。

一个数据源失败时，其他区块继续展示。

加载骨架必须匹配最终内容尺寸，避免页面跳动。

图表交互

支持周期切换、缩放、十字光标、图例开关和数据时间显示。

移动端提供明确的周期按钮，不依赖精细鼠标手势。

验收重点

从市场进入股票，再返回市场时，恢复原行业、Tab、筛选和滚动位置。

报告和分析入口保持同一股票上下文。

4.4 市场看板

保留能力

  • 指数概览。
  • 行业涨跌榜和成分股。
  • 强势股和题材归因。
  • 北向资金和行业资金。
  • 快讯和个股新闻。

统一区块状态

每个数据区块都使用统一的数据状态外壳：

  • 加载中。
  • 正常。
  • 真实空数据。
  • 请求失败。
  • 缓存陈旧。
  • 部分成功。

“暂无数据”和“数据源请求失败”必须使用不同文案。

钻取交互

点击行业展开成分股。

点击股票进入股票工作区。

点击题材可筛选相关股票。

所有钻取状态可通过返回操作恢复。

刷新策略

仅刷新可见页面。

后台浏览器标签页降频。

手动刷新有短防抖，并继续使用服务端缓存约束。

4.5 任务中心

任务列表

支持活动、已完成、失败、已取消、股票和日期筛选。

字段包括股票、分析日期、状态、当前阶段、耗时、调用统计和创建时间。

桌面使用表格。

移动端使用摘要卡片，不压缩成多列窄表格。

任务详情

包含：

  • 状态头。
  • 最后服务端更新时间。
  • 十二阶段时间线。
  • LLM 和工具调用统计。
  • Token 统计。
  • 已完成阶段的部分报告。
  • 非敏感配置摘要。
  • 错误信息与安全任务 ID。
  • 暂停、恢复、取消和重试操作。
  • 完成后的报告入口。

阶段报告

不再静默截断 3000 字。

长内容默认折叠，但可以展开完整文本。

控制操作

点击暂停后先显示“暂停中”。

Worker 在安全边界确认后才显示“已暂停”。

取消必须二次确认。

取消后保留已产生的阶段成果和审计记录，不能简单清空。

验收重点

运行中可以自由切换页面。

查看历史报告不会丢失任务控制入口。

刷新和重连不会增加模型调用次数。

4.6 报告库

列表能力

  • 游标分页。
  • 股票筛选。
  • 分析日期和生成日期筛选。
  • 信号筛选。
  • 同股票同日期多版本展示。
  • 返回列表时恢复筛选与滚动位置。

不再使用固定 30 条或 100 条截断。

报告版本

每次成功分析生成独立 report_id。

重跑生成新版本，并关联来源任务。

旧版文件只作为迁移来源和兼容投影，不再作为新版主存储。

4.7 报告阅读器

桌面布局

顶部是股票、分析日期、信号、目标价、止损参考和时间范围。

元信息区显示生成时间、模型配置摘要、任务 ID 和数据质量状态。

正文最大宽度建议 760–840px。

右侧使用粘性目录，并高亮当前章节。

操作包括返回、同标的其他版本、重新分析、下载 Markdown 和生成 PDF。

移动布局

信号头部压缩为核心信息。

目录改为抽屉。

多空辩论和风控角色使用分段控件或折叠区。

支持章节深链接和返回原阅读位置。

内容完整性

缺失字段显示“—”，不得编造。

网页、Markdown 和 PDF 必须来自同一规范化报告结构。

同一报告刚完成时与重新打开时，章节和信号必须一致。

4.8 报告导出

打开报告

只读取报告正文和元数据。

不得生成 PDF。

不得请求外部行情。

Markdown

直接从冻结的报告内容生成。

重复下载应得到相同内容。

PDF

只有用户明确点击后才生成。

生成期间正文仍可阅读。

缓存键使用 report_id + content_hash + exporter_version。

失败不影响正文和 Markdown。

数据快照

新版任务在完成时冻结报告正文和导出图表所需的数据快照。

旧报告没有图表快照时，允许补数导出，但必须明确标注“导出时补充数据”及对应时间。

不得把补数图表伪装成原分析时快照。

4.9 交易日志

首期保持独立服务。

新版只提供原生导航外壳和集成状态。

状态包括可用、启动中和不可用。

不可用时提供手动启动指引和新窗口打开，不影响主站其他功能。

地址通过配置管理，默认继续使用 127.0.0.1:8502。

桌面端按内容或视口调整高度。

移动端优先使用单滚动容器。

主题消息必须校验目标来源，不再使用任意目标的 postMessage。

日志自己的录入、流水和指标验收仍由日志项目负责。

4.10 设置页

包含：

  • 模型供应商和模型组合。
  • Base URL。
  • 并行分析师开关及实验性说明。
  • 行情刷新偏好。
  • 主题和密度。
  • 报告导出偏好。
  • 交易日志地址。
  • 数据目录、版本和 Worker 状态的只读信息。

API Key 只从服务端环境读取。

设置接口永远不返回密钥。

配置修改只影响新任务。

已有任务继续使用创建时的配置快照。

五、视觉与设计系统

5.1 视觉方向

整体风格定位为“克制、密集但清晰的专业研究工具”。

保留现有品牌橙作为操作强调色。

用深色中性色建立专业感，但不把整个界面做成纯黑交易终端。

信息层级优先于装饰。

卡片只用于真正独立的信息分组，不为每段文字重复加卡片。

采用 4px 基础间距单位。

桌面表格提供紧凑和舒适两档密度。

报告阅读默认使用舒适密度。

普通状态切换使用 120–200ms 动效。

不使用持续吸引注意的装饰动画。

任务运行状态可以使用轻量指示，但必须支持 prefers-reduced-motion。

页面加载优先使用稳定骨架，避免大面积闪烁和布局位移。

PreferenceService

负责非敏感偏好。

七、任务、数据与接口设计

7.1 核心数据表

表 关键内容
jobs 任务 ID、股票、分析日期、状态、控制请求、配置快照、配置哈希、幂等键、重试来源、当前阶段、统计、错误、租约和时间
job_stages 任务与阶段唯一键、阶段状态、阶段报告、开始和完成时间
job_events 单调事件序号、任务 ID、事件类型、小型载荷和时间
reports 报告 ID、来源任务、股票、分析日期、信号、规范化状态、原始状态、内容哈希、数据快照清单、来源和时间
app_settings 少量非敏感用户偏好
worker_lease 单行 Worker 锁、执行者 ID、心跳和租约到期时间

SQLite 开启外键、WAL 和合理忙等待。

WAL 是 SQLite 的日志模式，可降低读写互相阻塞。

事务保持短小。

数据库和备份放在本地磁盘。

7.2 配置快照

创建任务时，服务端生成完整配置。

嵌套配置必须深拷贝。

模型、供应商、Base URL、并行开关、数据供应商、语言和图适配器版本参与配置哈希。

Worker 为每个任务使用独立结果目录。

八、旧数据迁移与双栈策略

8.1 基线保护

开始前必须记录当前提交、未提交补丁、依赖约束和配置清单。

保留独立旧版目录和虚拟环境。

每个高风险阶段建立恢复标签和物理副本。

不得在唯一可用目录上直接进行不可逆迁移。

8.2 报告迁移

  1. 备份整个 ~/.tradingagents。
  2. 扫描旧 full_states_log_*.json。
  3. 校验股票、日期和 JSON 结构。
  4. 原样保存旧状态，并生成统一读取结构。
  5. 用“旧路径 + 内容哈希”保证重复导入幂等。
  6. 旧报告不伪造运行任务，来源标为 legacy。
  7. 文件修改时间只作为迁移元数据，不能冒充真实生成时间。
  8. 已被覆盖的旧版本标记为不可恢复。

8.3 未完成任务迁移

旧记录缺少完整配置和执行归属。

统一导入为“旧版未完成记录”或“已中断”。

不自动进入队列。

有匹配检查点时允许人工续跑。

否则要求用户确认参数后创建新任务。

8.4 设置、缓存与日志

从旧模型配置迁移非敏感偏好。

API Key 继续只读环境变量。

缓存、检查点和记忆文件原地保留。

交易日志数据完全不触碰。

8.5 唯一分析写入者

双栈运行期间必须明确唯一分析写入者：

ACTIVE_ANALYSIS_UI=legacy | next

legacy 模式下，只有旧版能创建分析，新版任务提交返回冲突。

next 模式下，只有新版 Worker 能创建分析，旧版分析入口禁用。

不能允许两个入口同时执行分析图。

8.6 报告兼容投影

新版每次成功报告写入独立任务目录和 SQLite。

同时把同股票、同日期最新成功报告投影到旧版文件，供旧 Streamlit 阅读。

投影前备份并原子替换。

旧版本报告不回写到旧文件系统。

因此旧版只能看到同键最新报告，新版保留全部版本。

投影失败不影响新版报告成功状态，但必须显示兼容警告。

8.7 灰度顺序

  1. 新版只读上线报告、市场和导航。
  2. 使用假图完成任务、崩溃、重连和迁移验收。
  3. 人工批准一次有费用上限的真实模型 Canary。Canary 是小范围真实验证。
  4. 新版主用一周，旧版保持可进入。
  5. 稳定后切换默认启动入口。
  6. 旧版继续保留一个观察周期。

8.8 回滚条件与步骤

出现重复模型执行、报告字段丢失、任务错误自动重跑或数据损坏时立即回滚。

回滚步骤：

  1. 禁止新版创建任务。
  2. 当前运行任务等待终态或协作取消。
  3. 将唯一写入者切回旧版。
  4. 验证最新兼容投影能由旧版打开。
  5. 保留新版只读入口，以访问多个报告版本。
  6. 数据库迁移保持新增式，不要求降级。
  7. 数据损坏时停止写入，再恢复 SQLite 和 ~/.tradingagents 备份。
  8. 回滚过程不触碰交易日志。

10.2 性能指标

在 P0 确定的基准机器和生产构建上测量。

  • 缓存命中后的路由切换 p95 不超过 300ms。
  • 报告元数据和正文 GET p95 不超过 500ms，外部网络调用为 0。
  • 10,000 条报告元数据下，50 条分页和基础筛选 p95 不超过 500ms。
  • 股票快照暖缓存 p95 不超过 1.5 秒。
  • 正常供应商冷加载 p95 不超过 4 秒，单区块失败不阻塞其他区块。
  • 任务创建 REST 响应 p95 不超过 500ms，不包含实际图执行。
  • Worker 阶段变化到浏览器可见 p95 不超过 2 秒。
  • SSE 网络恢复后 5 秒内开始重连，重连不创建新任务。
  • PDF 缓存命中下载准备不超过 500ms。
  • 固定大报告首次 PDF 生成 p95 不超过 15 秒，失败时正文始终可用。
  • 核心页面 LCP 不超过 2.5 秒，CLS 不超过 0.1，缓存交互 INP 不超过 200ms。

10.3 费用与可靠性硬指标

  • 20 个并发重复启动请求，假图构造次数严格为 1。
  • Worker 崩溃测试中，自动付费重放次数严格为 0。
  • 刷新、返回、查看历史和 SSE 重连产生的新任务数严格为 0。
  • 同股票同日期重跑后，旧报告仍可打开且内容不变。
  • 取消任务不能晚写入成功状态。

10.4 移动与可访问性指标

  • 核心流程满足 WCAG 2.2 AA。
  • 核心页面 axe critical/serious 问题为 0。
  • 正文和关键控件对比度至少 4.5:1。
  • 全部主流程仅键盘可完成，焦点清晰可见。
  • 360px 和 390px 无页面横向溢出。
  • 触控目标至少 44px。
  • 开启减少动态效果后，无持续脉冲和自动数字滚动。
  • 长报告完整可读，交易日志无不可控双层滚动。

十一、安全、成本与数据治理

11.1 安全

  • 默认只绑定 127.0.0.1。
  • 局域网或公网访问前必须增加认证和访问控制。
  • 生产环境由 FastAPI 同源提供前端，默认关闭宽松 CORS。
  • API Key 不进入前端、SQLite、事件、报告、URL 和错误响应。
  • Base URL、代理地址和异常日志需要脱敏。
  • 报告 Markdown 禁止不可信原始 HTML。
  • 外部新闻链接只允许 HTTP/HTTPS。
  • 文件读取按任务或报告 ID 查询，接口不接收任意文件路径。
  • iframe 消息校验来源和数据结构。
  • 默认错误响应只返回安全消息和请求 ID，详细堆栈仅写服务端日志。
  • Python 和 npm 依赖纳入漏洞检查。

11.2 成本

不新增付费基础设施。

模型成本通过幂等、禁用自动重试和显式付费确认控制。

没有价格配置时，只显示调用和 Token，不伪造人民币成本。

行情仅按可见页面轮询。

PDF 按需生成。

单 Worker 会带来任务排队，这是为避免配置污染和重复费用而接受的明确权衡。

11.3 数据治理

报告正文是历史研究快照。

每次报告都有内容哈希和导出版本。

新报告的图表输入尽量随任务冻结。

旧报告补数时必须标注补数时间。

非交易时段不伪装为实时。

请求失败但有旧数据时标为陈旧。

没有旧数据时标为错误。

真实空结果才标为空数据。

十二、主要风险与应对

风险 等级 应对
付费图在崩溃、重连和重试中重复执行 最高 单 Worker、数据库租约、幂等键、终态保护、不自动重放、人工续跑和崩溃对账
全局配置和检查点造成任务间污染 高 图只在 Worker 加载、严格串行、完整配置快照、同股票日期冲突保护
Runner 抽取导致核心分析语义漂移 高 保留核心调用顺序，使用假图做新旧黄金样本对照，不在本项目优化 Agent
双栈同时写入导致报告再次覆盖 高 唯一写入者、新版独立任务目录、旧文件只作兼容投影
检查点被误认为可无损恢复 高 验证配置和图版本，无法验证则新建任务，界面如实描述
外部数据接口异常或结构变化 中高 固定样本测试、部分成功、错误/空/陈旧分离和供应商超时预算
SSE 重连出现事件丢失或重复 UI 状态 中 持久事件序号、断线续传、权威快照和终态关闭
SQLite 锁等待影响任务事件 中 WAL、忙等待、短事务和事件限频，绝不因数据库重试而重跑图
PDF 继续产生隐藏网络副作用 中 GET 无副作用测试、显式生成、内容哈希缓存和图表局部失败
移动图表、长报告和表格工作量被低估 中 从 P2 起持续移动测试，不在最后一周集中补
交易日志跨域通信和高度适配 中 来源校验、消息版本、健康降级和新窗口回退
功能范围膨胀 中 按功能等价清单验收，报告对比和关注列表延后

最难部分的技术判断

付费分析图无法在任意崩溃点同时绝对保证“不重复模型调用”和“自动无缝续跑”。

本计划优先选择费用安全和状态可信。

系统宁可标记为 interrupted 并等待人工确认，也不擅自自动重跑。

这是整个升级中不能为了界面体验而牺牲的原则。

十三、工程执行规则

13.1 小批次交付

每个阶段拆成可独立审查和回退的小提交。

任务内核、报告迁移、页面重构和视觉调整不混在同一个大提交中。

高风险改造前建立恢复标签和物理副本。

现有未提交工作不得被无意覆盖或混入新功能提交。

13.2 契约先行

P0 先确定任务状态、报告字段、数据状态和接口结构。

前后端依据同一契约并行开发。

前端不直接读取 Python 私有对象。

后端不返回 Streamlit session 或服务器任意文件路径。

13.3 默认不使用真实模型

开发和 CI 默认使用假图、模拟报告和固定行情样本。

真实模型只在人工 Canary 中运行。

每次真实调用记录任务 ID、模型、配置哈希和调用次数。

13.4 浏览器证据优先

前端完成不能只看类型检查和测试通过。

必须逐页检查桌面和手机截图。

必须实际操作搜索、创建、刷新、跨页、暂停、恢复、取消、阅读和导出。

必须记录 console、pageerror、横向溢出和核心操作耗时。

13.5 旧版持续可运行

每个阶段结束都验证旧版启动和旧报告打开。

新版未达到等价验收前，不删除旧 Streamlit。

十五、建议评审时确认的五个决策

  1. 是否接受“React + FastAPI + 独立单 Worker + SQLite + SSE”的技术路线。
  2. 是否接受完整替代需要 15–21 人周，而不是一次性换皮。
  3. 是否接受单 Worker 串行带来的任务排队，以换取配置隔离和费用安全。
  4. 是否接受中断任务默认不自动重跑，必须由用户明确续跑或重新分析。
  5. 是否接受交易日志首期继续独立，不合并代码和数据库。

这五项确认后，P0 即可开始。

  • SPA：单页前端应用。页面切换主要由浏览器路由完成，不必每次整页刷新。
  • Worker：独立后台执行进程。这里专门运行分析图，不负责网页接口。
  • SSE：服务端向浏览器持续发送事件的单向通道。适合任务进度。
  • 幂等：同一个请求重复提交时，只产生一次实际效果。用于防止重复创建付费任务。
  • 配置快照：任务创建时冻结的一份完整参数。后续修改设置不影响已创建任务。
  • 报告版本：每次成功分析对应的独立报告。重跑不会覆盖旧版本。
  • WAL：SQLite 的预写日志模式。用于改善读写并发和崩溃恢复。
  • 租约：Worker 对任务执行权的有时限登记。用于避免多个执行者同时认领同一任务。
  • 检查点：分析流程在安全节点保存的状态。只有配置和图版本匹配时才可续跑。
  • Canary：小范围真实验证。这里指一次人工批准、限制费用的真实模型分析。
  • p95：95% 的测量结果不超过该数值。用于避免只看平均速度。
  • LCP/CLS/INP：分别衡量主要内容出现速度、布局跳动和交互响应。
  • WCAG 2.2 AA：一套网页可访问性标准，覆盖对比度、键盘和辅助技术等要求。
