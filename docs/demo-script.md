# Demo 录制脚本（README 界面预览 GIF / 视频）

目的：让陌生访客在 README 上 30 秒内"看到系统跑起来"。两种路线：

- **自动化（推荐，可重复）**：`scripts/make_demo_gif.py` 用 Playwright 驱动真实页面逐帧截图，PIL 合成 GIF，直接产出 `assets/demo.gif`；
- **人工录屏（更流畅，可加解说）**：按下面的分镜表用 OBS / ScreenToGif / Win+G 手动录，导出 GIF 或 MP4（MP4 命名 `assets/demo.mp4`，README 里替换 `<img>` 为 `<video>`）。

## 自动化路线

```bash
# 终端 1：启动 Web（或用 --launch 让脚本自己拉起）
streamlit run web/app.py

# 终端 2：录制（默认输出 assets/demo.gif，960px 宽）
python scripts/make_demo_gif.py
```

要点：

- 视口 1920×1080 最饱满；≤1680px 指数条自动换行到第二行（响应式顶栏），1440/1600 同样干净可录，不再需要刻意避开；
- 自动化分镜：boot 动画 → AI 分析首页 → 数据看板 → 分区切「强势股归因」→ 分区切「资金流」→ 主题切换 → 侧边栏；每步 best-effort，单个控件没找到不会中断，结束打印 ✓/✗ 报告；
- **个股 K 线周期切换自动路线录不到**——该区块由页面顶部搜索框（自定义组件，Playwright 无法触达）驱动；需要 K 线镜头走下面的人工路线；
- 连续相同帧会自动合并（时长累加），成品 >10MB 时：减小 `--scale`（0.4）或拉长 `--interval`（0.9）；
- 录完检查 `assets/demo.gif` 后提交，README「30 秒概览」已引用。

## 人工分镜表（约 25 秒）

录制前准备：浏览器无痕窗口（避免旧缓存/localStorage 主题残留）、1920×1080、缩放 100%。

| # | 时间 | 画面 | 操作 | 目的 |
|---|------|------|------|------|
| 1 | 0-4s | boot 动画 | 打开 `http://localhost:8501`，等 7 分析师节点点亮汇聚 | 展示启动过渡遮罩 |
| 2 | 4-8s | AI 分析报告首页 | 停留，鼠标缓慢划过报告卡片 | 展示分析报告形态 |
| 3 | 8-14s | 实时数据看板 | 顶部切「实时数据看板」，等 K 线/估值指标渲染 | 展示实时数据能力 |
| 4 | 14-18s | K 线周期 | 点「5日」→「30日」各停 2s | 展示交互性 |
| 5 | 18-22s | 主题切换 | 点右上角"灯绳"切暗色 | 展示即时主题切换 |
| 6 | 22-25s | 侧边栏 | 点 ☰ 展开（代码输入/模型配置/历史记录），停 2s | 展示配置入口 |

录后处理（ScreenToGif：裁剪 → 降帧 10fps → 缩放 50% → 另存 `assets/demo.gif`）。

## 录制红线

- **收盘时段看板指数显示 `--` + 已收盘标签**：属正常状态，不必重录；交易时段录数字更饱满。
- **不要在录屏里出现真实 API Key**：侧边栏镜头只展示布局，不展开 key 输入框；录完逐帧检查。
- GIF 里的股票数据是公开行情，无合规问题；分析报告若用真实 LLM 输出，注明"仅供学习研究"。
